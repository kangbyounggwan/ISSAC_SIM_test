# WB5 회전의 발 디딤 검증 — 2026-10-02

후속 JM 적용: [공식 H1 이동–좌회전–이동 연결](JM_WALK_TURN_20261002.md). 공식 native asset 기준의 별도 세션이며, 기존 WB5/그리퍼 개조 H1의 호환 성공과 구분한다.

## 요청과 범위

사용자의 “둘 다 가만히 있다”는 지적에 따라, 회전각 숫자가 아닌 실제 발 이륙·재착지 및 몸통/골반 동작을 검증한다. 학습과 보상 변경은 하지 않는다. 원본 WB5와 1,000회 goal-pose 후보의 체크포인트를 수정하거나 운영에 교체하지 않는다.

## 실행 전에 고정한 비교 조건

- 로컬 Isaac Sim 5.1 / Isaac Lab / RTX 4080 SUPER, 평지의 JM 개조 H1. AWS 시험이 아니다.
- 같은 평가 실행기, 물리 설정, seed `20261002`, 초기 root 위치/방향, 목표 좌/우 90°.
- 2초 정착 → 12초 목표 회전 → 4초 제동/유지. 목표와 허용오차 변경 없음.
- 원본 WB5는 같은 관측의 첫 69개 입력만 사용하고 후보는 추가 목표 7개를 포함한 76개를 사용한다. 같은 피드백 명령 규칙을 사용하되, 로봇 상태가 달라지면 실제 명령값은 달라질 수 있으며 이를 기록한다.
- 물리 200Hz / 정책·상태 기록 50Hz / 영상 1280×720, 25fps. 카메라는 위치만 따라가며 월드 좌표 이동량을 별도로 측정한다.
- 실행 중 root 위치·속도 및 관절각을 직접 쓰지 않는다. 정책 출력으로 관절 위치 목표를 구동한다. 초기화는 기존 reset 절차를 그대로 사용한다.
- 자동 episode reset 전에 정지해서 낙상이나 순간 이동을 영상에서 숨기지 않는다.
- 실제 물리 step 후에도 19관절의 PD/힘 제한이 계약값과 같은지 주기적으로 검사한다.

## 측정 항목과 판정

양발의 접촉력, 위치·자세·속도, air/contact time, 골반·몸통 yaw, 19관절 위치·속도·목표, 정책 출력과 실제 적용 명령을 기록한다.

진단용 “확인된 이륙→재착지”는 다음을 모두 만족해야 한다.

1. 직전 지지 접촉 ≥20N.
2. 접촉력 <5N 구간이 0.08초 이상.
3. 지지 때보다 발목 rigid body 원점이 20mm 이상 상승.
4. 이후 접촉력 ≥20N을 0.08초 이상 유지하는 착지 확인.

이 기준은 실행 전에 고정하며, 실패 결과를 통과시키려고 사후 완화하지 않는다. 접촉 해제만 있고 높이 변화가 없는 경우, 초기 공중 낙하, 접촉 노이즈를 정상 발 디딤으로 세지 않는다. 원시 신호와 기준 미충족 구간도 함께 보존한다.

발목 원점 높이는 발바닥 전체의 정확한 지상고가 아니며, 50Hz 표본은 아주 짧은 접촉을 놓칠 수 있다. 발 전체 net force는 발바닥 압력 분포가 아니다. 두 발이 접촉한 채 yaw가 바뀌는 동작은 피벗/미끄러짐 가능성을 별도로 검토하며 이륙 발걸음으로 세지 않는다. 이 시험 하나로 JM 랙 앞 회전이나 파지 운반을 인증하지 않는다.

현재 목표 관측/방향 보상은 `root heading`(골반)을 사용하며, 발의 방향이나 몸통 정면을 회전 완료 조건으로 함께 보지 않는다. 이것이 몸 전체가 회전하지 않았어도 **부분적인 방향 보상**을 얻을 수 있는 경로임은 코드/센서에서 확인했다. 다만 최종 성공 조건까지 통과한 것은 아니다. 전체 학습 실패를 이 요인 하나만으로 설명하거나 인과관계가 완전히 분리됐다고 주장하지 않는다.

원본은 한쪽 발을 한 번 재배치했지만 좌우 교대 디딤을 지속하지 못했다. 원본 좌회전의 오른발에는 기준 미달 이륙 두 건도 있었다(최대 상승 18.2mm/7.9mm). 이를 숨기지 않으며, “정확히 한 번만 움직였다”가 아니라 고정된 20mm/80ms 기준을 통과한 동작이 한 번이라는 의미다. 후보는 기준 미달을 포함해 80ms 이상 접촉 해제 구간 자체가 없었다.

별도로 공식 H1 자산 + 공식 정책 + 공식 PD/기본 자세를 사용하는 수정 비교기에 발 계측을 추가해 좌/우 시험을 완료했다.

공식 기준선 프로토콜은 기존 비교와 동일한 **2초 정지 → 10초 yaw ±0.30rad/s → 2초 정지**다. 이는 좌/우 90° 목표 실험과 명령·자산·환경이 다르므로 “모델 가중치 하나만의 대조”가 아니다. 목적은 별도 공식 기준선에서 실제 발 디딤 회전을 재현할 수 있는지 확인하는 것이다. 기존 20cm 이동 제한과 15° 자세 중단 기준은 유지한다. NVIDIA의 설치된 정책과 설정을 사용하는 별도 계측 실행기이며, NVIDIA 자동 테스트를 그대로 실행했다고 주장하지 않는다.

공식 기준선은 **실제 발 디딤 회전이 가능함**을 보여준다. 그러나 정지 명령에서도 제자리 디딤이 남고, 마지막 시점에 두 발 안정 지지가 모두 성립하지 않았다. 따라서 우회전 추종 기준 통과를 목표 자세 정착이나 랙 앞 정밀 도킹 성공으로 확대하지 않는다. 현재 목표각 시험과는 다른 속도 명령 시험이므로, 90° 목표 오차 표에 섞지 않는다.

회전 구간 시작인 2초에 이미 공중에 있던 발을 새로운 이륙으로 중복 계산하지 않도록 분석기를 보완했다. 초기 좌회전 원시 집계의 26/25에서 그 1건을 제외한 **25/25**가 검증 집계다. 수정 전 원시 결과는 보존하고 `footstep_validated.json` 및 `official_foot_summary.json`을 최종 수치로 사용한다. 물리 실험이나 판정 임계값은 바꾸지 않았다.

공식 계측의 제한: `RigidPrim` 접촉 준비가 발에 contact-report API와 sleep threshold=0을 설정함을 소스/세션 속성에서 확인했다. 접촉 안정화는 끄지 않았고 목표·힘·관절 동작을 직접 주입하지 않았다. 다만 이를 센서 없는 과거 실행과 물성까지 완전히 동일한 재실행으로 부르면 안 된다. 과거 9월 30일 기록과 이번 세션에는 작성된 drive 속성 차이도 있어, 과거 수치와의 차이를 정책 개선이나 재학습 효과로 해석하지 않는다. 원본 USD 파일에는 저장하지 않았다.

공식 영상은 720p/25fps/351프레임/14.04초, 센서 기록은 50Hz 701행이다. 좌측 영상 5프레임, 우측 영상 1프레임에 검은 주 화면이 있어 **영상 품질 QA는 실패**로 기록한다. 물리 시계 오차는 최대 약 0.000000313초였고 접촉·자세 데이터는 연속 기록됐다. 검은 프레임을 삭제하거나 합성으로 숨기지 않았다. 원본/후보의 4개 영상에는 이 문제가 없다.

## 현재 판단과 다음 수정 우선순위

1. 1,000회 후보는 운영에 사용하거나 그대로 추가 학습하지 않는다. 현재 고정 초기상태 대조에서는 원본보다 발 재배치가 줄었고 몸통 정면 회전도 줄었다.
2. 골반 yaw 수치만으로 회전 개선을 해석하지 않는다. 몸통 정면, 양발 지지 방향과 골반의 일관성, 디딤 이력, 정지 뒤 방향 유지까지 평가에 포함해야 한다.
3. 학습을 수정할 경우 먼저 회전 명령에서의 **하중 이동→반대 발 이륙→방향을 바꾼 재착지**를 만드는 한 가지 변경을 별도 실험으로 검증한다. 허용 관절 범위 확대나 임의 관절각 수정으로 해결하지 않는다.
4. 발걸음이 확인된 다음에만 위치 이탈 억제와 90°/180° 정지 정확도를 별도 단계로 다룬다. 공식 기준선의 회전 성공도 JM 랙 앞에서의 안전한 제자리 회전 성공과는 다르다.

이번 요청에서는 위 학습 수정은 실행하지 않았고, 진단 기록/분석 코드와 문서만 추가했다.
