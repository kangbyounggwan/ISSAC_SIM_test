### 영상 대조와 한계

- 전체 영상의 모든 프레임을 디코드 검사하고 12개 균등 시각 프레임을 시각 검토했다. 전신과 양다리가 프레임 안에 보이며, 실제 발 디딤으로 방향이 바뀐 후 B 쪽으로 이동한다.
- `DONE`은 **연속 이동 프로토콜 완료**다. 양발 고정 정지·파지 준비 완료를 의미하지 않는다. 001의 엄격 정지 시험은 그대로 FAIL이다.
- 210.93mm 밀림을 200mm 합격으로 반올림하지 않는다. 랙 바로 앞 회전에는 추가 정밀 제어가 필요하다.
- 원시 바닥 접촉의 최소 separation은 초기 낙하/접촉을 포함해 약 −12.8mm다. 본 결과가 충돌 solver의 관통 오차 0 또는 실물 접촉 안전을 인증하는 것은 아니다.
- 영상에서 기존 개조 H1 material reference 경고가 로그에 있으나 해당 로봇은 session에서 비활성화했다. 실제 구동 로봇은 공식 native H1이며 원본 월드를 저장하지 않았다.
- **기존 WB5/그리퍼 장착 H1에는 아직 이 결과를 그대로 배포하면 안 된다.** 다음 별도 과제는 정지 시 발구름을 끝내는 제어와 그리퍼·질량 변경 시 보행 계약 호환성 검증이다.

## 실험 범위 / 사전 고정 계획

- 실제 JM 공장 월드의 바닥·설비 collider를 유지한다. 원본 USD와 정책은 수정하지 않는다.
- 검증된 NVIDIA 공식 H1 asset + 공식 69-observation / 19-action 정책을 별도 session layer에 배치한다. 기존 그리퍼 장착 H1은 이 세션에서만 비활성화한다.
- 따라서 본 실험은 기존 WB5 및 그리퍼 장착 H1의 배포 성공, 파지·운반 성공이 아니다. RL 재학습도 하지 않는다.
- Fable CLI를 사용할 수 없어 교차 시나리오 논의는 수행하지 못했다.
- 고정 seed 2159858089의 기하학적 랜덤 스폰을 재사용한다. 결과에 따라 seed나 목표를 다시 고르지 않는다.
- 시작 XY = (35.5232820, 15.9689446), 초기 yaw = +90°. A = 시작 + (0, 1m), B = 시작 + (-1m, 1m).
- 두 직선 경로는 사전 AABB 검사에서 0.65m 여유 조건을 통과했다. 실제 collider 접촉은 별도로 기록한다.

| 구간 | 실행 / 종료 조건 |
|---|---|
| SETTLE | 초기 물리 안정화 후 몸체 속도 <0.10m/s, yaw rate <0.15rad/s를 1초 유지 |
| MOVE_A | 북쪽 약 1m, 위치 오차 <0.12m, yaw 오차 <7° |
| BRAKE_A | 명령 0, 위치 오차 <0.18m 및 몸체 정지 조건 1초 |
| LEFT_TURN | world yaw +180°까지 좌회전, 오차 <7° |
| BRAKE_TURN | 명령 0, yaw 오차 <7° 및 몸체 정지 조건 1초 |
| MOVE_B | 서쪽 약 1m, 위치 오차 <0.12m, yaw 오차 <7° |
| FINAL_STOP | 최종 위치 오차 <0.18m 및 몸체 정지 조건 1초 |

- 속도 명령 상한: 전진 0.30m/s, 횡/후진 0.12m/s, 좌회전 0.30rad/s. 명령 가속도 제한 0.4m/s² / 0.6rad/s².
- 기울기 15° 이상, root 높이 floor+0.65m 미만, 설비 접촉 >0.20N, 회전 중 위치 이탈 >0.35m, 단계 timeout이면 중단한다.
- 제자리 회전 품질 기준 0.20m는 별도 판정한다. 0.35m 안전 중단 한계와 혼동하지 않는다.
- 몸체 정지와 양발 정지는 별개다. 공식 정책의 제자리 발구름이 남을 수 있으므로 발 접촉·이륙/착지를 별도 보고한다.
- root 좌표는 시작 배치에서만 정하고 실행 중 쓰지 않는다. 관절은 정책 출력 + 공식 default/scale/PD로 제어한다.
- 200Hz physics / 50Hz policy, 25fps 1280×720 전신 영상, 50Hz 상태·발 접촉 및 200Hz 원시 접촉 로그를 저장한다.
- A*, X-NavDP, UniLM-Nav는 이번 고정 L자 연결 실험에 사용하지 않는다.

## 실행 결과

### 001: strict_stops

`artifacts/jm_walk_turn_20261002/official_native_001/`

- 6.005초에 SETTLE_TIMEOUT. 이동/회전은 시작하지 않음.
- 최대 기울기 5.97°, 환경 접촉 보고 0, 발 이륙/착지 좌우 각각 14회.
- zero command에서도 주기적인 발구름 때문에 몸체 속도/각속도 정지 조건을 1초 연속 만족하지 못함. 넘어짐이나 랙 접촉 실패가 아님.
- 이 실패를 보존한다. 기존 1초/0.10m/s/0.15rad/s 정지 합격 기준은 바꾸지 않는다.

### 002: 별도 continuous 연결 시험 (실행 전 정의)

첫 실험은 정지 정책 검증과 이동 연결 검증이 한 gate로 묶여 있었다. 사용자 요청인 이동+회전 연결을 독립 시험으로 분리한다.

- 변경 변수: 상위 단계 프로토콜만 `strict_stops` → `continuous`.
- 정책, asset, spawn seed/좌표, 목표 A/B, PD, 물리, 속도/가속도 상한, 위치/방향 허용오차, 충돌/기울기/회전 이탈 abort 기준은 동일하다.
- WARMUP 2초 → MOVE_A → LEFT_TURN → MOVE_B → STOP_AUDIT 2초.
- 중간 정지 gate를 통과했다고 주장하지 않는다. 기존 strict_stops는 여전히 실패 상태다.
- 최종 2초 zero command는 정지 성능 **관찰**이며 정지 합격 gate가 아니다. 발구름 횟수와 최종 오차를 별도로 보고한다.
- 실패 자세를 이어받지 않고 동일 초기 상태에서 새 프로세스로 시작한다.

### 기록 저장 수정 / 003 재현

- 002는 16.83초에 DONE까지 도달했고 영상·telemetry·접촉 로그를 보존했다. 그러나 마지막 `result.json` 저장 시 phase event 안의 NumPy float32를 JSON이 처리하지 못했다.
- 003은 event 기록 숫자만 Python float으로 변환하는 수정이다. 동작 계산, 목표, 판정, 정책, 물리는 변경하지 않았다.
- 숫자 직렬화 회귀 테스트를 추가했다. 단계 제어 테스트 8개 + 기존 발 디딤 분석 테스트 7개를 사용한다.
- 002의 `exception.txt`는 삭제하지 않으며, 최종 보고용 영상/결과는 003의 완결된 산출물을 사용한다.

## 구성과 재현 방법

```text
JM 원본 USD / 실제 바닥·설비 collider (읽기 전용)
   └─ 실험 session layer: 기존 로봇만 비활성화 → 공식 H1 추가
       ├─ jm_sequence.py : 고정 A/B 목표 + 상위 단계 / 속도 명령
       ├─ 공식 H1 policy : 69 관측 → 19 관절 action, 50Hz
       ├─ PhysX          : PD 구동·중력·접촉, 200Hz
       ├─ telemetry      : root/torso/foot pose, command, contact, 50Hz
       ├─ raw_contacts   : 실제 collider pair/impulse, 200Hz
       └─ 720p 영상      : 전체 몸/다리 + 단계/명령/오차, 25fps
```

```powershell
C:\isaacsim\python.bat jm_wb5_turn/run_jm_walk_turn.py --mode continuous --out artifacts/jm_walk_turn_20261002/새_출력_폴더
python jm_wb5_turn/audit_jm_walk_turn.py artifacts/jm_walk_turn_20261002/새_출력_폴더
```

출력 폴더가 이미 있으면 실행을 거부한다. `strict_stops` 옵션은 기존 엄격 정지 gate를 그대로 보존한다. 카메라가 어두운 프레임을 반환하면 같은 물리 시각에서만 재렌더하며, 과거 프레임으로 대체하지 않는다.
