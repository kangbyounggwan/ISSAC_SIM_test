# JM 첫 랙 정지 → 파지 가정 → A* 옆 랙 언로드 위치 주행

## 최신 시작 조건 변경: 랜덤 스폰

사용자 요청에 따라 `--mission jm_transfer`의 기본 시작은 이제 **랜덤 위치**다. 아래 001~006은 기존 고정 스폰의 역사적 실행 기록이다.

- 영역: JM 2층 픽업 랙 앞 통로 X=[35.4,37.0]m, Y=[15.8,16.8]m. 월드 전체 랜덤이 아니다.
- 시작 방향은 기존 authored 방향(+Y 부근), 높이·관절 기본값·보행 정책은 유지한다. 위치 랜덤화와 yaw 랜덤화를 섞지 않는다.
- 설비와 대기 중인 다른 로봇의 실제 collider AABB를 0.65m 확장해 점유 여부를 검사한다. 통과 지점 중 한 곳을 초기화 전에 선택한다. 이 초기 기하 여유 검사는 동적/전체 몸체 안전 인증은 아니다.
- 생략 시 실행마다 새 uint32 seed 생성. seed·영역·거부한 초기 후보·선택 위치·실측 초기 위치를 `spawn.json`/`manifest.json`에 기록한다.
- `--spawn-seed <기록된 seed>`로 같은 초기 위치를 재현한다. 렌더·물리 실행 전체가 비트 단위로 동일하다는 뜻은 아니다.
- 초기 기하 검사에서만 최대 256개 후보를 확인한다. 실제 주행 실패 후 다른 위치를 뽑아 성공 후보만 남기지 않는다. 유효 지점이 없으면 시작하지 않는다.
- 에피소드 초기화 시 로봇 root 위치를 딱 한 번 설정한다. 그 이후 root 위치 변경 없이 실제 보행한다. 원본 USD는 저장/수정하지 않는다.
- 픽업 (36.170834,18.200058)m / 언로드 (38.420834,18.200058)m와 성공·안전 판정은 그대로다. 도킹 이후 보행 전환 실패가 해결됐다는 의미가 아니다.

기존 고정 위치 시험을 재현하려면 반드시 `--spawn authored`를 사용한다. 랜덤 초기화 코드와 연결 회귀 테스트는 42개 통과했다.

### 랜덤 시험 원인 대조 — 제어 코드와 실측 기록

사용자 질문에 대한 진단이며 이 절 작성 시 제어 코드를 수정하거나 재실행하지 않았다.

1. **5.2초 / 목표 거리 약 0.770m**에 X-NavDP 추종에서 `GOAL_POSE_DOCK`으로 넘어갔다. 해당 제어는 0.8m 이내에서 고정 전환하고 이후 X-NavDP 재추론을 하지 않는다. 그러므로 마지막 실패를 X-NavDP 단독 문제로 단정할 수 없다.
2. 가까운 거리 **0.3m 안에서는 목표점을 향하는 방향 대신 최종 yaw 90.862°를 우선**하도록 구현되어 있다. 횡이동 명령은 0이고 전진은 양수만 허용한다. 따라서 옆으로 남은 위치 오차를 고칠 수 없는 상태가 생긴다.
3. **9.0초** 실제 위치 (36.359612,18.197596)m, 목표 (36.170834,18.200058)m: X 오차 **+18.878cm**, Y 오차 **-0.246cm**. 목표까지 18.879cm여서 18cm 도착 조건 밖인데, 진행 방향으로는 거의 도착해 전진 명령이 0이 됐다. 현재 방향 고정/횡이동 0 구조로는 이 X 오차를 직접 줄이지 못한다.
4. **9.0→12.5초** 전진/횡이동 명령 0인 동안에도 yaw 보정 명령은 남아 있었다. 몸체가 X 약 +6.68cm, Y 약 +29.48cm 이동했다. 따라서 '모든 명령이 0인데 미끄러짐'이라고 하지는 않는다. 현재 정지/회전 명령 추종이 충분히 안정적이지 않다는 실측이며, 순수 관성·마찰·정책·설정 중 무엇이 근본 원인인지는 분리 실험이 필요하다.
5. **12.5초** 목표 거리 38.834cm, 몸체 반경 proxy 추가 여유 -8.459mm가 되어 `FOOTPRINT_EXCLUSION` 종료. 환경 접촉은 0N이다. 실제 mesh 충돌이 확인된 것이 아니라 보수적인 경계 검사 위반이다. 파지 가정/A* 옆 랙 이동은 아직 시작하지 않았다.

확인된 구현상 문제는 **옆 방향 오차가 남았는데 최종 몸통 방향으로 조기 전환하는 도킹 제어**, 확인된 동작상 문제는 **정지·회전 중 위치 유지 부족**이다. 랜덤 스폰은 이 약점을 드러낸 조건이고, A*는 이 실행의 실패 단계에 관여하지 않았다. 다음 수정 우선순위는 위치 정렬→감속/안정 정지→최종 yaw 정렬의 전환 조건을 분리하고, 각 구간의 실제 명령 추종을 검증하는 것이다. 성공 반경을 넓혀 통과시키는 해결은 아니다.

## 요청·범위

사용자가 파지 위치 도착 시 손에 파지했다고 가정하고 옆 랙까지 A*로 이동하도록 요청했다.
파지 가정은 **논리 상태값**이다. 물건을 손에 붙이거나 물체 pose를 이동하지 않는다. 실제 파지·리프트·적재 하중 보행·언로드/해제 성공으로 주장하지 않는다.
원본 월드·로봇 관절 기본값·보행 가중치는 유지하고 시뮬레이션 세션에서만 실행한다. 로컬 Isaac Sim이며 AWS나 실물 로봇 시험이 아니다.

## 작업과 목표

1. H1_1을 위 랜덤 영역의 기하 검사 통과 위치에 초기화하고 RGB-D + X-NavDP로 접근한다. A* 중간 목표 미사용. 과거 001~006은 기존 시작점 (36.175,17.055)m이었다.
2. RACK_cont_008 앞 기존 파지 인계 기준 (36.170834, 18.200058)m / yaw 90.861967°에서 안정 정지한다.
3. 기존 도착 조건(18cm, 속도 0.10m/s 미만, yaw 15° 미만, yaw rate 0.15rad/s 미만, tilt 15° 미만)을 1초 만족하면 `ASSUMED_GRASP`로 전환하고 1초 대기한다.
4. 실제 측정된 정지 위치에서 옆 RACK_cont_009 앞 (38.420834, 18.200058)m까지 A*를 계산한다. 다른 로봇의 collider도 장애물에 포함한다.
5. 고정 H1 보행 정책으로 경로를 따라간다. 횡이동·후진 명령 없이 큰 방향 차이에서는 전진을 멈추고 회전한다.
6. 언로드 기준점에서 같은 방향/안정 정지 조건을 1초 유지하면 `UNLOAD_POSITION_REACHED`. 실제 제품 놓기는 실행하지 않는다.

009 랙 언로드 위치는 기존 008 정지 자세를 랙 간 X 차이 2.25m만큼 옮긴 후보다. 첫 물리 주행으로 정지 가능성을 확인하는 것이며 실제 언로드 IK/접촉 검증은 아니다. 제품의 최종 배치 위치가 아니라 **로봇의 언로드용 정지 위치**다.

## 검증과 기록

관련 단위 테스트 33개 통과. 픽업 전 transfer 차단, 대기 시간, 실제 측정점 A* 시작, 목표 점유 실패, 회전 전 전진 차단, 정지 진입 자체를 성공으로 오인하지 않는 것을 확인했다.

Fable: 현재 셸에서 호출 실행 파일을 찾지 못해 상호 검토 미완료. 합의 완료라고 표시하지 않는다.

003은 종료 시 이벤트 위치의 numpy float32 JSON 직렬화 오류가 추가로 발생했다. 영상 마지막 프레임·`telemetry_partial.json`에 실제 안전거리 실패가 남아 있으며 result.json 누락을 성공으로 처리하지 않는다. 이벤트 값 저장을 Python float로 수정하고 단위 테스트를 추가했다. 003 영상 189프레임(720p/24fps) 전체 디코딩 검사 오류 0, 종료 프레임 육안 확인.

002 이후 제자리 회전 정체(5초간 yaw 변화 1° 미만이며 계속 회전 명령)를 실패로 종료하는 감시 조건을 추가했다. 이 조건은 로봇 행동·목표·성공 조건을 바꾸지 않고 불필요한 반복을 중단한다. 모든 비교는 실패 자세를 다음 초기값으로 쓰지 않고 처음부터 시작한다.

005의 후퇴는 원래 픽업/언로드 목표를 이동한 것이 아니라 별도 철수 동작을 추가한 실험이다. 후퇴 속도 -0.12m/s, 실측 후퇴량 0.25m, 시간 제한 10초로 고정했다. 현재 보행으로 성공하지 않았으므로 채택하지 않는다.
006에서는 후퇴를 다시 제거해 004와 비교한다. 회전 후 전진 대신 랙 방향 yaw를 유지한 채 A* 경로 방향을 몸체 전진/횡이동 명령으로 변환한다. 기존 `H1RackVelocityActionCfg`의 횡이동 명령 범위가 존재한다는 사실과 실제 안정적인 옆걸음 검증은 구분한다.

004 영상 189프레임, 005 영상 191프레임을 전부 디코딩하여 720p/24fps/오류 0을 확인했다. 두 실행은 원본 월드 보존·루트 위치 쓰기 없음, 실제 물리 파지/언로드 없음이다.

006은 목표 거리 138.4mm였지만 속도 0.157m/s로 안정 정지 조건에 미달했고 추가 안전 여유 -2.5mm였다. 기록 접촉 0N이므로 실제 충돌이 관측되었다는 뜻이 아니라, 보수적인 몸체 반경 검사에 걸린 것이다. 목표 허용오차를 넓히거나 안전 검사를 꺼 성공으로 바꾸지 않았다.
006 영상 전체 160프레임(720p/24fps/6.67초) 디코딩 오류 0. 004·006의 마지막 프레임을 육안 검토했다. 테스트는 총 37개 통과했다. 이번에 띄운 추론 서비스/시뮬레이터는 종료했다.

## 다음 우선순위와 미확인 사항

1. 랙 도킹 후 1초뿐 아니라 출발 대기까지 위치·속도를 유지하는지 먼저 분리 검증한다. 같은 조건에서 초기 정지가 재현되지 않으므로 출발 제어 비교만으로 원인을 확정할 수 없다.
2. 알려진 빈 공간에서 **정지→회전/후퇴/옆걸음→정지** 명령 추종을 측정하고 검증된 동작만 도킹 상태와 연결한다. 지금 증거로는 보행 정책 자체의 한계와 연결 제어/시뮬레이터 영향이 분리되지 않았다.
3. 그 후 같은 픽업/언로드 좌표로 연속 미션을 재검증한다. 목적지 이동, 관절 수동 수정, 안전 여유 축소로 우회하지 않는다.

최종 코드에는 실패가 발생한 프레임에서 도착/파지 가정 상태가 새로 통과하지 못하도록 실패 우선 조건도 추가했다. 이 보호 조건은 종료 후 추가한 것으로 새 물리 실행을 주장하지 않는다. 기존 단일 월드 시험 경로는 유지하고 새 미션은 `--mission jm_transfer` 옵션에서만 활성화한다. 이 미션은 현재 실험 기능이며 운영 가능한 완료 기능으로 표시하지 않는다.
