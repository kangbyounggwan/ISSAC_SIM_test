# 휴머노이드 회전의 통상적 접근과 JM 적용 판단

조사일: 2026-10-01. 공식 코드와 원저자 논문을 웹에서 확인했다. 이번 요청은 조사이므로 제어 코드/학습/모델/원격 저장소는 변경하지 않았다. 아래 설계 제안은 아직 검증된 성능이 아니다. 외부 main 브랜치는 이후 바뀔 수 있으며 과거 WB5 서버의 라이브러리 버전을 확정하는 자료로 쓰지 않는다.

## 핵심

회전은 두 층으로 구분한다.

- 상위: 어디서 어떤 방향으로 얼마만큼 돌지, 주변에 회전할 공간이 있는지 결정.
- 하위: 발 지지/발 디딤/몸통 균형을 제어해 실제 회전속도를 만들어 냄.

목표 yaw만 주거나 A*를 바꾸는 것으로 하위 제자리 회전 능력이 생기는 것은 아니다. 반대로 회전 가능한 보행 정책만 있어도 랙 앞 작업 자세까지 안전하게 도착하는 경로가 자동으로 만들어지는 것은 아니다.

일반적인 stepping turn은 한쪽 다리로 지지하고 반대 발을 새 방향으로 옮기는 동작을 반복한다. 몸통만 비틀거나 root yaw를 직접 쓰는 방식과 다르다. 지지발의 미세 회전이 전부 금지되는 것은 아니지만, 통제되지 않은 발 미끄러짐을 정상 회전 성공으로 보지 않는다.

## 공식/연구 구현에서 확인한 선택지

| 계열 | 입력/방식 | 현재 JM에서의 의미 |
|---|---|---|
| 속도 명령 추종 RL | vx, vy, yaw-rate를 받아 관절 action 생성 | 현재 WB5와 가장 가까움. 하나의 정책에서 전진·회전·정지를 함께 학습 가능 |
| 발자국 계획 + RL | 다음 착지 위치/방향들을 정책에 제공 | 정밀한 발 디딤을 유도하는 대안. 현재 69입력 WB5에 그대로 추가할 수 없음 |
| 발자국 계획 + MPC/전신 제어 | 향후 착지·지지력·몸통 상태를 최적화 | 제약을 명시적으로 다루지만 현재 시스템 대비 도입/검증 범위가 큼 |

### 1. Unitree 제조사 H1 RL

[Unitree RL Lab H1 설정](https://github.com/unitreerobotics/unitree_rl_lab/blob/main/source/unitree_rl_lab/unitree_rl_lab/tasks/locomotion/robots/h1/velocity_env_cfg.py)에는 선속도/yaw 속도 추종, gait phase 관측, 좌우 발 위상 보상, 발 미끄러짐 및 접촉 제약이 있다. 별도 회전 모델만 필수인 구조는 아니다. 이 설정은 action scale/관측 스케일 등이 WB5와 달라 가중치나 보상만 무비판적으로 섞을 수 없다. 해당 제조사 코드가 JM 랙 앞 정밀 회전을 보증하지도 않는다.

### 2. 발자국 추종 RL

[Learning Bipedal Walking On Planned Footsteps For Humanoid Robots](https://arxiv.org/abs/2207.12644)는 다음 두 발자국 정보를 입력해 전방향 보행·제자리 회전·정지·계단을 다룬다. 연구 대상은 MuJoCo의 HRP5P/JVRC-1이며 H1용 즉시 교체 체크포인트가 아니다. [저자 코드](https://github.com/rohanpsingh/LearningHumanoidWalking)를 제공한다.

### 3. 발자국과 몸통을 함께 계획

[Orientation-Aware MPC](https://arxiv.org/abs/2205.15443)는 MIT Humanoid에서 몸통 회전과 발 위치 등을 함께 최적화한다. [RL-augmented MPC](https://arxiv.org/abs/2407.17683)는 DRACO 3의 발자국 계획에 RL을 결합한다. 현재 WB5를 그대로 쓰는 작은 수정이 아니라 별도 제어 시스템 도입에 해당한다.

## 상위 회전 제어에서 배울 점

[Nav2 Rotation Shim 공식 문서](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/controller_plugins/configuring_rotation_shim_controller/)는 방향 오차가 클 때 먼저 회전하고 경로 추종으로 전환한다. 각가속도 제한, 목표 근처 감속, 회전 중 footprint 충돌 예측도 제공한다.

중요: 문서의 전제는 이미 제자리 회전 가능한 로봇이며 차동/전방향 플랫폼이 대표다. 이것을 설치한다고 H1이 발을 움직이는 방법을 배우는 것은 아니다. Nav2 기본 회전속도/가속도를 그대로 H1에 복사하지 않는다.

JM에서는 이 '감속·회전·주행 전환' 원리를 참고하되, 발/팔의 동작 범위와 실제 회전 중 몸체 이동을 함께 평가해야 한다. 현재 0.38m 원형 footprint는 보수적인 단순 프록시이고 전신 충돌 인증은 아니다.

## WB5 학습에서 구체적으로 점검할 조건

[Isaac Lab reward 원본](https://github.com/isaac-sim/IsaacLab/blob/main/source/isaaclab_tasks/isaaclab_tasks/manager_based/locomotion/velocity/mdp/rewards.py)의 `feet_air_time_positive_biped`는 선속도 명령 크기가 0.1m/s보다 커야 작동한다. 따라서 vx=vy=0, yaw-rate≠0인 순수 회전에 이 보상은 기여하지 않는다. yaw 추종 등 다른 보상은 여전히 작동하므로 '회전을 절대 학습 못한다'는 의미는 아니다.

이전 로컬 조사에서 확인한 WB5 기반 설정과도 관련 있는 점검 항목이지만, 과거 서버의 실제 보상 버전과 실행 명령 분포를 확인해야 한다. 보상 gating 하나를 실패의 확정 원인으로 지목하지 않는다.

또 선속도만 0에 맞추는 속도 추종은 특정 세계 좌표에 계속 서 있는 것과 다르다. 작은 잔여속도가 누적되거나 발을 디딜 때 위치가 이동할 수 있으므로, 제자리 기준점으로부터의 변위를 따로 측정해야 한다. 발끝을 공중에서 옮기는 동작까지 위치 고정/정지 페널티로 억제하면 회전 자체를 방해할 수 있다.

## 현재 실험에 대한 해석 — 외부 논문이 아닌 우리 데이터

- WB5 JM 음의 yaw 회전은 약 21.25° 이후 정체했다.
- 양의 yaw는 회전하지만 이전 시험에서 평가 구간 XY drift가 약 51.2cm였다.
- PD/effort/clock이 유지되는 것은 확인됐으나 학습/배포의 바닥·초기화·접촉·관성까지 완전 일치한 것은 아니다.
- 최신 position-first 도킹은 목표 거리 11.2cm까지 줄었지만, 방향 정렬이 완료되지 않고 14.1초에 footprint 안전 경계를 넘어 중단됐다. 환경 접촉 센서 값은 0N이었다.

따라서 현재 문제는 경로와 하위 보행의 두 층에 걸쳐 있다. '가까이만 가면 된다', 'yaw 보상만 올리면 된다', '더 큰 회전 명령이면 해결된다'는 결론은 근거가 부족하다.

## JM 권고 — 아직 실행하지 않은 다음 실험

### 단기: 안전 공간에서 정렬 후 진입

랜덤 스폰 → 통로의 사전 정렬 위치 → 감속/실측 정지 확인 → 작업 방향으로 발 디딤 회전 → 안정 확인 → 짧은 직선 진입 → 최종 정지.

사전 정렬 위치는 최종 작업 자세에서 접근 방향의 반대로 떨어진 후보들 중 선택한다. 거리는 임의로 50cm/1m를 확정하지 않고 H1의 도달성, 실제 회전 drift, 주변 장애물, 최종 직선 통로를 함께 검증해 실험 전에 고정한다. 실패 후 목표/거리/허용오차를 자동 이동하지 않는다. 여유가 없으면 그 경로를 불가능으로 판정한다.

공간이 충분한 이동 구간에서는 전진과 회전을 함께 하는 완만한 곡선 경로도 후보지만, 그것이 WB5에서 더 안정적이라는 결과는 아직 없다. 제자리 회전 실패를 가리기 위해 임의로 270° 우회전/반대 방향 회전을 선택하지 않는다.

### 하위 보행: 독립된 회전·정지 평가 및 제한적 보강

1. 랙 없이 같은 JM 실행 계약에서 정지·좌/우 회전·걷기→정지→회전을 평가한다. 실제 발 접촉/들림, 골반 yaw, XY drift, 종료 후 잔여속도를 함께 저장한다.
2. 완전한 WB5 학습 원본 `model_1497.pt`를 확보하고 실제 학습/배포 계약을 확인한다. 현재 GitHub actor만으로 PPO 완전 재개가 된다고 취급하지 않는다.
3. 첫 학습 변경은 명령 분포: 정지, 순수 좌회전, 순수 우회전, 기존 전진을 명시적으로 포함. 보상/관절 제한/허용오차는 유지한다.
4. 다음 별도 실험에서 yaw-only에도 발 교대 디딤 보상이 작동하도록 검토한다. 임계값과 단위는 사전에 명시한다.
5. 이후 필요한 경우 정지/회전 중 기준점 drift와 잔여속도 항을 별도로 검토한다. 모든 보상을 한 번에 강화하지 않는다.
6. 좌우 90°/180°, 여러 고정 seed, 정지 유지, 기존 전진 성능 퇴행을 확인한 뒤 랙 앞 동작에 연결한다. 기존 drift 20cm 및 안전 gate를 실패 후 완화하지 않는다.

보행 정책 하나로 정지/회전/전진을 처리할 수 있다. 별도 turn policy는 가능한 설계 선택일 뿐 필수가 아니며, 분리할 경우 정책 전환 시 이전 action·접촉 위상·자세의 연속성까지 검증해야 한다.

## 실행 여부

이번에는 검색·소스 대조·설계 문서화만 했다. 코드 적용, 새 RL 학습, 체크포인트 교체, 추가 시뮬레이션, Git push는 하지 않았다.
