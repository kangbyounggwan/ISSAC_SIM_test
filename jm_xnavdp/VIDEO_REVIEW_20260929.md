## 전달 영상

두 월드를 Isaac Sim에서 열고 실제 모델 출력 경로를 월드 좌표에 표시해 촬영했다.
**정지된 월드의 진단 영상이다. X-NavDP가 로봇을 움직이는 영상이나 실시간 재계획 영상은 아니다.**
카메라 이동과 경로 표시 애니메이션만 있으며, 로봇을 예측 경로에 따라 좌표 이동시키지 않았다.

## 무엇을 보여주는가

- 메인 화면: 원본 공장 환경, 전체 H1, 작업 랙 또는 기존 seed42 랜덤 박스.
- 오른쪽: 이전 실제 추론에 사용한 RGB와 image-plane depth 저장 관측. 현재 움직이는 점검 카메라의 영상이 모델 입력인 것은 아니다.
- 파란 선: 기존 추론 결과의 선택 경로. 회색: 모델 후보 경로. 녹색 원: 목표.
- 0~6초: 관측과 환경 확인.
- 6~16초: 저장된 모델 경로의 지점을 순차 표시. 이는 예측 시각이나 실제 주행 시간의 재생이 아니라 설명용 표시다.
- 16~24초: 실행을 차단한 원인과 현재 한계 표시.
- 전체 프레임에 `정지 월드의 모델 경로 시각화 · 로봇 주행 아님` 표시.

JM은 기존 H1_1의 authored 초기 상태를 사용했다. KETI는 기존 시험의 출발 위치에 H1 자산을 표시용으로 참조했다. 두 경우 모두 물리 시간을 진행하지 않았으므로 화면의 정지 자세를 균형 유지 성공으로 해석하지 않는다. KETI 표시용 H1의 초기 배치는 실제 보행이나 순간이동 이동 궤적이 아니다.

기존 `jm_inference_001/result.json`, `keti_inference_001/result.json`을 읽었으며 촬영 중 새 모델 추론을 반복하지 않았다. 모델을 호출하지 않고 임의 경로를 만들어 넣은 것도 아니다. 모델 출력 경로를 `world_path` 좌표 변환으로 표시했고 선택 경로는 기록된 월드 좌표를 그대로 사용했다.

## 아직 보여줄 수 없는 것

X-NavDP 경로를 H1이 실제 추종하면서 새 RGB-D를 재관측하고, 장애물을 우회한 뒤 안정적으로 정지하는 전체 임무는 미실행이다. 목표 앞 감속·정지, 초기 되짚음 처리, 센서 기반 실행 구간 간섭 검사 이후 별도 물리 보행 영상으로 검증해야 한다. 이번 영상으로 기존 안정 정지 실패나 파지 문제가 해결됐다고 주장하지 않는다.
