# H1 회전 원인 분리 비교 — 2026-09-30

## 목적과 보존 원칙

현재 WB5 정책의 우회전 정체/좌회전 드리프트가 정책 자체인지, 개조 로봇 또는 배포 설정 차이인지 분리한다. 기존 정책·JM 월드·학습 작업은 변경하지 않는다. 이 문서는 실제 결과를 실행 후 추가한다.

## 고정된 시험 조건

- 로컬 Isaac Sim 5.1, RTX 4080 SUPER. AWS 학습이 아닌 격리된 물리 시뮬레이션.
- 평지의 동일 초기 위치 `(0,0,1.05)`, 초기 방향 0도. 시험 중 root 좌표 쓰기 없음.
- 2초 정지 명령 → 10초 yaw ±0.30rad/s → 2초 정지 명령.
- 물리 200Hz, 정책 50Hz, 각 실행을 새 프로세스에서 초기화.
- 720p / 24fps 전신 영상. 측정 구간 2.5~11.9초는 이전 진단과 동일.
- 평균·후반 방향 일치 yaw 속도 ≥0.10rad/s, 구간 XY 드리프트 ≤20cm, 기울기 <15도. 기존 기준 완화 없음.
- 평지에는 랙이 없으며 장애물 접촉 센서는 없음. 0으로 기록한 `contact_N`은 **접촉 검증이 아니라 해당 없음**이다. 결과의 `collision_validated=false` 유지.
- 공식 기준선은 공식 env 기본값 사용. 이후 WB5 배포 조건을 고정하고 정책/자산 하나씩만 바꿔 대조한다. 다른 기본 자세를 쓴 두 결과를 '가중치만 다른 비교'로 부르지 않는다.

## 비교 구성

1. 공식 H1 자산 + 공식 정책 + 공식 env 설정: 기준선.
2. 공식 H1 자산 + 공식 정책 + WB5 배포 설정: 배포 계약 차이 확인.
3. 공식 H1 자산 + WB5 정책 + WB5 배포 설정: 2번과 정책만 비교.
4. JM 개조 H1 자산 + 공식 정책 + WB5 배포 설정: 2번과 자산만 비교.
5. JM 개조 H1 자산 + WB5 정책 + WB5 배포 설정: 3번과 자산만, 4번과 정책만 비교.

각 필요한 구성에서 좌·우 방향을 별도 실행한다. 안전 기울기 초과 시 중단하며 실패 결과도 보존한다. 임의의 관절각 탐색·목표 변경·보상 변경·재학습은 하지 않는다.

공식 정책은 설치된 NVIDIA 예제의 자산 경로로 취득하고 SHA256, env YAML, 관절 순서/기본값/구동값 및 로봇 USD 물성 목록을 실행별로 보관한다. 현재 Fable CLI는 발견되지 않아 이번 실험에 Fable 합의가 있었다고 주장하지 않는다.

## 결과

### 비교 도구 오류 발견 및 제외

첫 평지 비교 9건은 **정책 성능 비교에서 제외**한다. 시작 직후 읽은 PD 값은 정상이어도 실제 물리 step 이후 USD/Fabric 동기화가 runtime-only 설정을 덮어썼다. `turn_compare_wb5_jm_pos_001/pd_after_step_20.json`에서 몸통/다리 등의 Kp가 기대 150~200이 아니라 약 **35809.86**, Kd가 기대 5가 아니라 **0**으로 바뀐 것이 확인됐다. 기존 JM 자산의 USD stiffness=625(degree 단위)가 다시 적용된 값이다.

따라서 이 도구로 측정한 초기 원본 정책 회전 116도/76cm 및 140도/73cm, 조합 변경 후 초기 자세 붕괴를 정책의 성능이나 결함으로 해석하지 않는다. 원시 결과는 삭제하지 않고 남긴다. 도구를 고쳐 **물리 초기화 전에 세션의 drive 값을 작성**하고, 실제 physics step 이후에도 몸통 19관절 PD가 같은지 검사하도록 했다. 원본 USD 파일은 저장하지 않는다.

기존 `run_physical.py`는 이미 물리 초기화 전에 drive 값을 작성하는 다른 경로다. 이 코드에서 동일 JM 월드·동일 seed·동일 정책으로 재현 실험을 우선 수행했으며, 기존 WB5 우회전 측정치(−21.2508679°, 드리프트 0.019763m)가 그대로 재현됐다. **새 비교 도구의 오류를 기존 JM 회전 문제의 원인이라고 혼동하지 않는다.**

WB5 우회전은 이번 재실행, 좌회전은 같은 seed·자산·설정의 이전 실행을 재분석했다. WB5 우회전 재실행의 기록 위치/yaw는 이전과 정확히 동일했다. 두 공식 시험은 회전 방향별 독립 성공/실패 증거가 아니라 **동일한 초기 정지 실패의 재현**이다.

회전 수치는 기존과 같은 2.5~11.9초 구간이다. 초기 정지 명령 0~2초의 WB5 이동량 24.36cm는 이 구간 드리프트와 별도다. 그래프는 0초 기준 전체 이동량을 그리므로 표의 구간 수치와 혼동하지 않는다. 새 실험 3건 모두 `source_world_unchanged=true`, 추론 호출 0, 실행 중 root 좌표 변경 없음.

평지 비교에는 15도 조기 중단 기준을 사용했다. JM 실행의 FALL 중단 기준(몸체 높이 0.65m 미만 또는 기울기 40도 이상)과 다르므로 조기 중단 시각을 서로 같은 낙상 시간으로 비교하지 않는다. 양쪽의 **회전 합격 기준**은 동일하지만, 정지 실패 시간이나 낙상 심각도 비교는 하지 않는다.

이 결과는 '공식 정책이 JM 로봇에 무조건 불가능하다'는 해석도 반박한다. **같은 JM 로봇 자산의 공식 정책이 평지에서는 회전하고, JM 실제 월드에서는 정지부터 실패한다.** 따라서 자산 질량 차이만을 단일 원인으로 확정할 수 없고, 초기화/바닥/월드 물리/실행기 차이까지 배포 조건을 맞춰야 한다.

### 한 변수 추가 대조

- 평지 WB5+JM의 바닥 반발계수만 0.8 → 0으로 변경: 여전히 정지 단계 기울기 초과. 반발계수 하나의 수정으로 해결되지 않음.
- 같은 평지 WB5+JM에서 초기 스폰 높이만 공식 예제의 1.05m → WB5 학습 코드의 0.98m로 변경(반발계수는 다시 기준선 0.8 유지): 여전히 정지 단계 기울기 초과. 높이 하나의 수정으로 해결되지 않음.
- 실패 후 목표 위치/관절 범위/성공 허용오차를 바꾼 것이 아니다. 별도 이름의 진단 실행에서 학습/공식 예제에 명시된 초기 조건과 바닥 응답을 각각 대조했다. 두 변경을 함께 적용한 결과는 없고, 이를 해결책이라고 주장하지 않는다.

## 확인된 차이와 남은 미확정 부분

원본 H1과 JM 자산의 선언된 rigid-body 질량 합은 각각 약 51.62kg / 60.16kg이다(USD 선언값 합이며 실측 유효 질량 인증 아님). 예를 들어 한쪽 허벅지 4.152 → 4.953kg, 정강이 1.721 → 2.824kg, 발목/발 링크 0.474 → 0.725kg이며 관절 추가 관성 armature도 0 → 0.1로 다르다. 기본 관절각/PD만 맞추면 같은 로봇이 되는 것이 아니다.

한편 평지에 놓은 **JM 자산과 JM 월드에 합성된 같은 자산**의 공통 링크 질량·질량중심·관성 및 관절 축·프레임·armature는 읽기 대조에서 일치했다. 즉 평지/JM 간 역전 결과를 'JM 월드에서 질량이 또 바뀌어서'라고 설명할 근거는 없다.

JM 바닥 slab에는 명시적인 physics material 바인딩이 없었다. 공식 평지 생성 API 기본값은 마찰 0.5/0.5, 반발계수 0.8이다. JM의 **실효 기본 접촉 물성**을 학습 설정과 같다고 가정하면 안 된다. 원본 월드 PhysicsScene의 GPU/60Hz 선언과 실제 실행의 CPU/MBP/200Hz 덮어쓰기 역시 구분해 기록해야 한다. 원본 선언만 읽어서 실제 실행 주기가 60Hz라고 결론내리지 않는다.

아직 초기화·접촉·관측/제어 구현 중 어떤 **단일 차이**가 평지/JM의 반대 결과를 만드는지는 분리되지 않았다. 또한 현재 WB5 우회전 정체가 학습 부족만의 문제인지도 확정하지 않았다.

## 권고: 모델 교체보다 실행 조건 통일 → WB5 정지/회전 보강

### 1순위 — 공통 실행 조건과 실측 검사부터 고정

학습/평가/실제 JM 실행에서 같은 설정 묶음을 사용한다: 자산 해시, 관절 순서, 기본 자세, 초기화 순서, PD/토크/속도 제한, 추가 관성, 발 collider, 바닥 재질과 결합 방식, solver 설정, 200Hz 물리/50Hz 정책, 관측 좌표계와 이전 action 처리. 최초 관측뿐 아니라 physics step 이후와 주행 중에도 실제 값이 유지되는지 검사한다.

다음 비교는 새 평지 전용 제어기를 늘리지 않고 **기존 JM 실행기 하나 안에서** 무장애물 기준 장면/실제 JM 장면을 대조하는 방식이 우선이다. 지금 얻은 결과만으로 바닥·질량·시작 높이를 동시에 바꾸거나 대규모 재학습하지 않는다.

### 2순위 — 기존 WB5 복제본에서 정지·양방향 회전만 단계적으로 보강

실행 조건을 고정한 뒤에도 우회전 정체가 재현되면, 처음부터 보행을 재학습하는 대신 기존 WB5를 보존한 별도 체크포인트에서 보강한다.

1. 첫 학습 실험: 보상은 유지하고, `vx=vy=0`인 좌/우 yaw 명령과 정지→회전→정지 표본을 명시적으로 추가. 기존 전진 표본도 유지해 보행 퇴행 평가.
2. 이후 별도 실험: 순수 yaw에서도 발 교대 디딤 보상이 작동하도록 변경. 현재 선속도 기반 gating 문제를 다룬다.
3. 이후 별도 실험: 정지/회전 중 위치 드리프트와 잔여 속도를 억제하는 보상을 검토. 보상 변경들을 한 번에 묶지 않는다.
4. 단일 seed 성공을 합격으로 삼지 말고, 고정 seed 세트에서 좌/우 90°·180°, 걷기→정지→회전, 정지 유지, 기존 직진 성능을 각각 평가한다. 기존 20cm 회전 드리프트 기준과 JM 도착 기준은 자동 완화하지 않는다.

### 3순위 — 랙 접근의 마지막 위치/방향 전환 수정

현재 도킹은 거리 30cm 안에서 최종 yaw를 먼저 맞추지만 성공 반경은 18cm이며, 횡방향 오차 회복이 없다. 이 불일치는 보행 모델을 고쳐도 남는다. 목표점은 유지하고, 통로에서 랙 진입 방향을 미리 맞춘 후 직진 접근하도록 계획하며, 최종 위치 조건을 충족하지 못하면 완료 처리하지 않고 안전한 위치 회복 상태로 돌아가도록 한다. 랙 바로 앞에서 큰 회전으로 문제를 덮지 않는다.

**결정:** 현 JM의 공식 정책 즉시 교체는 채택하지 않음. 현재 WB5 원본 유지. 새 RL 학습은 아직 시작하지 않았고, 생산 내비게이션 기본 정책도 바꾸지 않았다. 파지/옆 랙 이송/언로드 성공은 이번 시험의 범위 밖이다.
