# JM H1 실행 검사·도킹 보정 반영 — 2026-09-30

## 범위와 불변 조건

사용자 요청: 이전 비교에서 제안한 개선을 반영한다.
로컬 RTX 4080 SUPER / Isaac Sim 5.1에서 실행한다. AWS 학습이나 Git push는 하지 않는다.
WB5 원본 모델, 월드 원본, 관절 기본각, PD/토크, 물성, 랜덤 스폰 seed를 보존한다.
주행 도중 root pose를 쓰지 않는다. 파지/하중/언로드 성공을 가정해 이 검증을 통과시키지 않는다.

## 실제 코드 반영

1. `h1_contract.py`: 기존 학습 상수에서 19관절 순서/기본각을 읽고, 실행 PD/effort와 69차원 관측 순서를 한 모듈로 묶음. 물리 200Hz, 정책 50Hz, action scale 0.5 유지.
2. `RuntimeAudit`: 초기화 및 physics step 1/20/40, 이후 매 200 step마다 **실제 PhysX PD/effort와 물리 시간**을 읽고 기록. 불일치 시 파일을 남기고 중단하며 값을 자동 수정하지 않음.
3. `docking.py`: 실험 옵션에서는 거리 30cm에서 최종 yaw를 먼저 맞추던 분기를 제거. 기존 18cm 위치 조건 안에서만 최종 yaw 정렬. 바깥이면 목표 위치 방향을 먼저 향하고 전진. 큰 heading 오차에서는 전진 중단. 후진/횡이동은 추가하지 않음. **물리 시험 실패 후 기본값은 legacy 유지, 새 방식은 명시적 `--docking-controller position_first`에서만 사용한다.**
4. `transfer.py`: unload 정렬에 진입한 후 18cm 밖으로 밀리면 latch 해제, 기존 경로 추종으로 복귀. 진입 기준 12cm는 유지.
5. `--dock-probe-start`: 이전 주행의 **속도 명령만** 정해진 시각까지 재현하고 새 도킹으로 전환하는 진단. 좌표/관절 궤적을 재생하거나 새 XNav 추론 성공으로 표기하지 않음. 제한시간은 고정, 실패에 따라 자동 연장하지 않음.

외부 성공 판정은 그대로: 거리 <18cm, yaw <15°, 속도 <0.1m/s, yaw-rate <0.15rad/s, tilt <15°를 1초 유지.
진단 완료와 도킹 성공은 다른 필드로 저장한다. `pass=false`인 진단 기록을 전체 미션 성공으로 해석하지 않는다.

## 학습 착수 조건 — 아직 미충족

이 검사 통과는 **body19 제어값/clock 유지**만 뜻한다. 학습과 JM 배포의 바닥 접촉 물성, 초기화, appendage mimic 매핑, 관절 추가 관성/속도 제한까지 일치한다는 증거가 아니다.
따라서 런타임 검사 통과만으로 재학습을 자동 시작하지 않는다.

로컬 WB5 자료에는 추론용 TorchScript actor가 있으며, 기존 PPO 재개용 전체 checkpoint는 해당 디렉터리에서 확인되지 않았다. 이것을 `runner.load`에 넣어 학습 재개가 가능하다고 주장하지 않는다.
기존 학습기는 `/workspace/jm` 서버 자산/체크포인트 경로를 사용한다. 로컬 학습 경로와 asset 계약을 검증하기 전 그대로 실행하지 않는다.

다음 학습 실험은 계약 확인 후 **명령 분포 하나만 변경**한다: 정지, 순수 좌회전, 순수 우회전, 기존 전진을 포함. 기존 보상/종료/관절 제한을 유지한다. 순수 회전 발 교대 보상과 드리프트 보상은 그 다음 별도 실험이다.
평가: 고정 seed별 좌/우 90°·180°, 걷기→정지→회전, 정지 유지, 직진 퇴행. 기존 회전 drift 20cm 기준을 유지한다.

Fable 협의는 현재 CLI 부재로 수행하지 못했다. 외부 합의 완료로 기록하지 않는다.

13초에 위치 오차 15.7cm였지만 방향 오차는 -72.3°였다. 기존 12초 위치 오차 25.4cm/방향 오차 -44.6° 대비 새 방식은 같은 12초 21.5cm/-56.3°: **위치를 줄이는 대신 최종 방향은 악화했다.** 마지막 11.2cm만 보고 개선 완료로 보고하지 않는다.

프레임을 직접 확인하면 로봇이 랙 앞 목표로 접근하며 큰 각도로 돌아 최종 작업 방향을 유지하지 못한다. 이는 '도킹 방향을 너무 일찍 맞추는 버그'를 제거하는 것만으로는 안전한 작업 자세를 만들 수 없다는 결과다. 다음 후보는 **랙 앞이 아니라 통로의 사전 정렬 위치에서 작업 방향을 맞춘 뒤 직선 진입**하는 방식이다. 별도 경로 실험으로 검증해야 하며, 현재 WB5 우회전/정지 약점은 그대로 남아 있다.
