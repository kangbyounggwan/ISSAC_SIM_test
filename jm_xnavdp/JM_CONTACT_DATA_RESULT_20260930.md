# 랙 회전 접촉 데이터 재현 결과 — 2026-09-30

## 결론

**검사한 0~24초 구간에서 실제 PhysX 랙/작업대 접촉은 없다.** 합산 힘 0N만 재확인한 것이 아니라, 기존 필터와 독립적인 물리 엔진의 접촉 쌍/접촉점 보고를 200Hz로 수집했다. 보고된 접촉 쌍은 오른발-바닥, 왼발-바닥 두 개뿐이었다.

기존 `jm_single_robot_001`의 같은 시작 seed 2159858089, 같은 가중치·관절·PD·목표·월드를 사용하고, 저장된 10Hz 속도 명령을 다시 보행 정책에 입력했다. 몸체 좌표 재생/텔레포트가 아니다. 비교한 241개 시점의 몸체 위치와 yaw가 원 기록과 정확히 일치했다. 따라서 화면상 겹침을 의심했던 랙 앞 회전 구간을 다른 경로로 피한 시험이 아니다.

이는 현재 **충돌 형상/설정 하에서의 물리 접촉 판정**이다. 시각 mesh와 collider가 완전히 일치한다는 검증 또는 로봇 자체 충돌 검증은 아니다. 이전 다른 실험이나 24초 이후 전체 이력의 비접촉 인증으로 확대하지 않는다.

### 실제 검출된 접촉 쌍

1. `/World/H1Fleet/H1_1/right_ankle_link/foot_box` ↔ `/World/Dadong/F2/slab`: 접촉점 누적 14,413개.
2. `/World/H1Fleet/H1_1/left_ankle_link/foot_box` ↔ `/World/Dadong/F2/slab`: 접촉점 누적 14,573개.

접촉점 누적은 매 물리 스텝마다 보고되는 점을 합친 것이며 서로 다른 위치의 개수가 아니다. 바닥 접촉 검출로 보고 경로가 전부 0만 반환하는 상태는 아님을 확인했다. 별도의 랙 강제 충돌 양성 대조를 수행한 것은 아니다.

바닥 접촉 보고의 최소 separation은 오른발 -4.26mm / 왼발 -16.38mm다. 이 값은 **발-바닥 접촉**의 solver separation이고 랙 관통 수치가 아니다. 바닥 접촉 품질/물성 대조 시 추가 확인할 사항이다.

## 계측 방법과 범위

- 로봇 각 rigid body의 PhysxContactReportAPI threshold를 0으로 설정했다. 접촉 보고를 추가했으며 질량·마찰·형상·관절 제한을 변경하지 않았다.
- 매 실제 물리 스텝 후 `get_contact_report()`에서 collider 경로, 접촉점, normal, impulse, separation을 읽었다. 모든 로봇 접촉 쌍을 보존하고 랙/작업대 점은 상세 저장한다.
- 로봇/랙008/작업셀 H1_1 관련 collider 95개가 목록에 있으며 collisionEnabled=false인 항목은 없었다. 이것만으로 시각 mesh와 동일하다고 주장하지 않는다.
- 기존 필터된 힘 검사·보행·안전 종료 조건은 유지했다. 새 시험은 회전 보정이나 내비게이션 성공 시험이 아니다.
- 결과의 `pass=false`는 전체 임무 성공으로 표시하지 않기 위한 값이다. `diagnostic_completed=true`, `failure=null`로 24초 계측을 정상 완료했다.
