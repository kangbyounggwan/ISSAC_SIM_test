## 실제 실행에서 발견한 제한

1. **JM의 선택 경로는 정지 목표 방향으로 약 237.6mm 초과한다.** 모델은 지역 경로 제안기이지 우리 정밀 도킹 제어기가 아니다. 38cm 반경 몸체 proxy와 원본 설비 AABB를 이용한 사후 검사에서 적재판 주변 여유 -113.2mm였다. 이는 보수적 형상 검사 실패이며 실제 mesh 관통이 관측됐다는 뜻은 아니다. 그래도 이 경로 전체를 그대로 실행해서는 안 된다.
2. **KETI 초기 지점 간 전진 좌표가 최대 47.8mm 감소한다.** 뒤로 되짚는 성분을 기존 전진 중심 보행에 그대로 전달하지 않았다. 예측 전진 길이는 약 1.25m로 박스 앞면까지 도달하지도 않는다. 따라서 오른쪽으로 휘는 경로가 나왔다고 전체 장애물 우회를 입증한 것은 아니다.
3. **현재 서비스는 관측·추론용이다.** 시뮬레이터에서 지속적인 센서 입력을 보내고 보행 결과를 다시 관측하는 실시간 반복 제어는 미연결이다. 저장 관측을 API로 보냈을 때 오래된 입력으로 판정하고 실행 명령 0을 반환하는 것을 확인했다.
4. **모델의 humanoid 조건은 G1이다.** H1 몸체·카메라·제동거리 차이는 검증되지 않았다. 기존 KETI 안정 정지 실패도 해결된 것으로 표시하지 않는다.

후보가 실패한 뒤 목표·오차·물체 위치·관절 값을 수정하지 않았다. 검사 통과를 위해 새로운 seed를 탐색하거나 후진 gate를 완화하지 않았다.

사후 정답 형상 검사는 [output_audit_001.json](../artifacts/xnavdp_20260929/output_audit_001.json)에 있으며 **그 형상/박스 좌표를 모델 입력으로 사용하지 않았다.** 모델 입력은 카메라 RGB-D, 상대 목표, 자기 위치/방향과 관측 이력이다.

```text

  test_adapter.py / test_service.py

```

이번에 실행한 흐름:

**원본 월드 → 정지 카메라 RGB-D → 고정된 X-NavDP 가중치 → 후보/선택 경로 → 좌표 변환·실행 조건 검사 → 기록(제어 차단)**.

향후 주행 연결:

**지속 센서 관측 → 비동기 모델 서버 → 최신 경로 → 센서 기반 간섭·속도 제한 → 기존 H1 보행 → 실제 도착/정지 재검증 → 기존 파지 IK**.

경로가 실패하거나 관측이 오래되면 과거 경로를 계속 실행하지 않는다. 정지 명령 전송과 실제 안정 정지는 구별한다. 현재 adapter의 속도 변환은 우리 전진 중심 추종 제안이며 upstream acados MPC를 실행한 것은 아니다. 전역 경로/미지 공간 탐색을 전부 대체하는 코드도 아니다.

## 재실행

워크스페이스 루트 PowerShell에서 실행한다. 결과 폴더는 항상 새 이름을 사용한다.

```powershell
# 최초 준비: 기존 환경을 보존한다. 이미 설치된 현재 PC에서는 생략 가능.
.\jm_xnavdp\setup_local.ps1

# 계약/거부 조건 테스트
.\.conda\xnavdp-runtime\Scripts\python.exe -m unittest jm_xnavdp.test_adapter jm_xnavdp.test_service -v

# 저장된 실제 JM RGB-D에서 GPU 추론
.\.conda\xnavdp-runtime\Scripts\python.exe jm_xnavdp/infer_observation.py --observation artifacts/xnavdp_20260929/jm_capture_002 --out artifacts/xnavdp_20260929/jm_inference_next

# 로컬 추론 API. H1 제어는 활성화하지 않는다.
.\.conda\xnavdp-runtime\Scripts\python.exe jm_xnavdp/server.py --port 8891
```

다른 터미널에서 `probe_service.py --observation ... --out ...json`으로 서비스 통신을 확인할 수 있다. `/health`는 로드 상태, `/reset`은 단일 클라이언트 이력 초기화, `/infer`는 RGB-D NPZ를 받는다. 외부 네트워크에 공개하지 않는다. 연구용 Flask 서비스이며 운영용 서비스로 보증하지 않는다.

## 검증과 다음 작업

- 좌표계 회전, 잘못된 배열, NaN, 오래된 관측, 후진 제한, 좌우 속도 제한, HTTP 잘못된 입력 거부 등 **15개 테스트 통과**.
- 환경 의존성 검사 통과. JM/KETI 원본 레이어 해시 유지 확인.
- 실제 HTTP 추론 응답 저장: `jm_service_001.json`, `keti_service_001.json`. 로봇 명령은 0회.
- 테스트용 로컬 서버는 검증 후 종료했다. 다음 실행 시 위 명령으로 다시 시작한다.
- 상세 모델 로드 기록: 각 inference 폴더의 `load_audit.json`.

다음 순서는 **목표 앞 감속/정지 연결 및 센서 기반 짧은 실행 구간 검증 → 이동 중 관측을 반복하는 경로 재계산 → H1 물리 주행**이다. 초기 후진 성분 처리도 별도 단일 변수로 검증해야 한다. 단순히 전체 예측 궤적을 끝까지 실행하거나 G1 보행 checkpoint로 교체하지 않는다.

새 시나리오를 Fable과 합의했다고 주장하지 않는다. 이번에는 기존 JM 초기 자세와 기존 KETI seed42를 사용한 코드/입력 연결 검사만 수행했다. 외부 프로젝트 정보 전송 검토가 완료되지 않아 새 Fable 리뷰는 하지 않았다.
