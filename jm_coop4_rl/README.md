# JM COOP-4 RL — 랙 접근·정지 학습

2026-09-09 / 로컬 Windows, RTX 4080 SUPER 16GB.

## 현재 실제 실행

- `runs/smoke_001`: 32개 환경, PPO2회 업데이트 및 정책 저장 완료. 본학습 횟수와 별개.
- `runs/h1_nav_001`: **512개 환경, 목표1,000회 본학습 실행 시작**. 상위 actor는 smoke에서 이어받지 않고 새로 초기화했다.
- 시작 점검(4회): loss 유한, 실제 업데이트 진행, GPU 메모리 약5.9GB. 누적 초기355개 에피소드에서 성공0·낙상0·랙/접촉 실패128·시간초과227. 이는 초기 상태이며 최종 성능이 아니다.
- 1회 약3.5초의 초기 측정 속도라 전체는 약1시간 규모의 추정이다. 부하에 따라 변할 수 있다.
- **사용자 승인으로 RL용 JM 월드는 H1 4대로 통일했다.** 원본 Atlas 2대 + H1 2대 월드는 보존했다. 전체 공장 도달 검증은 학습 성능과 구분한다.
- `runs/fleet_h1_004_video`: **model_200으로 실제 JM 월드의 H1 4대 모두 도킹·1초 정지 PASS**. 4.5초 동작, 720p 영상 저장. 지정 시작점에서 1회 검증한 결과이며 반복 성공률은 아직 아니다.

[실시간 상태 JSON](runs/h1_nav_001/status.json) · [학습 이력](runs/h1_nav_001/training_history.jsonl) · [실행 설정](runs/h1_nav_001/manifest.json)

`status.json`은 실행 중 갱신된다. 이 문서의 초기 점검 수치를 최신 성능으로 사용하지 않는다.

[H1 4대 통일·실제 검증 기록](H1_FLEET_UNIFICATION.md)에서 로봇 교체, 목표 매핑, 제어 단위 오류 수정과 공장 재생 결과를 확인한다.

## 초기화의 의미

이전 `jm_coop4`의 제자리 팔 신호 실행을 종료하고, 이 폴더에 새 랙 접근 작업을 분리했다.
기존 파일·영상·체크포인트는 삭제하지 않는다. 원본 공장 USD를 저장하지 않는다.
H1의 **새 상위 이동 정책(actor/critic/optimizer)은 초기화**하고, 검증된 하위 보행 정책은 고정해서 재사용한다.
다리를 처음부터 다시 학습하는 것과 구분한다.

## 목표

```text
에피소드 초기 위치에서 시작
→ 학습 정책이 전진/횡이동/회전 속도 선택
→ 기존 H1 보행 정책이 실제 관절 구동
→ 할당 랙 앞에 도착
→ 랙을 향해 정렬
→ 낮은 속도로 1초 정지 유지
→ 성공 종료
```

실행 중 root 좌표 직접 이동, 골반 fixed joint, 물체 부착은 사용하지 않는다.
에피소드 reset에서만 초기 위치를 쓴다. 파지/삽입/리프트는 이번 범위에서 제외한다.

## 4대 H1 구성 — 사용자 승인 반영

원본 월드는 Atlas 2대와 H1 2대다. 2026-09-09 사용자 승인에 따라 별도 RL용 월드 `assets/jm_world_h1_fleet.usda`에서만 H1 4대로 통일했다.

| 구분 | H1 | Atlas |
|---|---|---|
| 현재 재사용 보행 정책 | WB5 정책 있음, 입력69→출력19 실제 확인 | 조사 범위 내 없음 |
| 보행용 로컬 자산 | WB7 standalone, 33 DOF, 동적·floating root, collider45개 | 원본은 kinematic/전시용 |
| 새 랙 이동 학습 | 고정 보행 위 상위 PPO부터 가능 | 발·몸 collider와 동적 자산 검증, 별도 보행 정책부터 필요 |
| 정책 혼용 | 같은 H1 인스턴스에는 공유 가능 | H1 weights 직접 적용 불가 |

Atlas 실제 검사: 발바닥 접촉체가 양발 총16개 반경0.1mm 구이고 몸통·다리 collider가 없다.
원본 USD/URDF 질량 합계182.36kg, 다른 XML과 일부 몸통 질량도 다르다.
이 상태에서 몸통이 랙을 뚫는데도 성공이라 판정하는 실험을 시작하면 안 된다.

4대는 동일한 상위 이동 정책과 동일한 동결 H1 보행 정책을 공유한다. 정책은 같지만 각자 다른 랙 상대 위치를 관측하고 독립적으로 행동한다.
4대 모두 33개 회전 관절, collider 45개, 동적 articulation이며 골반의 월드 고정은 없다. **구성 검증과 4대 도달 성공은 별도 판정한다.**

## 학습 구조

```text
랙 상대 위치/방향 + 몸체 상태 + 이전 이동 명령
                  ↓
새 PPO 이동 정책 (상위, 학습 대상)
                  ↓ vx / vy / yaw-rate
기존 WB5 H1 보행 정책 (동결, 입력69·출력19)
                  ↓ 19개 관절 위치 행동
PhysX 동적 로봇 + 지면 + 랙 충돌체
                  ↓ 실제 도착/속도/기울기
보상 + 성공/실패 종료 + PPO 업데이트
```

`wb6_nav_validated`는 검증 영상 묶음 이름이며 별도 학습된 navigation 모델명이 아니다.
이전 WB6의 랙 방향·속도 선택은 규칙 기반이고, 랜덤 시작의 엄격 평가 결과도10/64였다.
새 상위 정책을 별도로 학습하는 이유다.

## 고정 실험 계획

- 단일 랙 앞 제한된 시작 영역에서 먼저 학습한다. 거대한 공장 전체를512번 복제하지 않는다.
- 평면 위치 도착, 방향 정렬, 실제 정지 유지 조건을 모두 만족해야 성공한다.
- 낙상/위험 경계 진입/시간초과는 성공으로 세지 않는다.
- 기본 본학습은1,000 PPO iterations. 준비용2회 smoke는 본학습 횟수에 포함하지 않는다.
- 50회마다 checkpoint, 모든 iteration의 loss/reward/종료 지표를 로컬 JSONL·TensorBoard에 기록한다.
- 250/500/750/1000회에 비교한다. 학습횟수와 독립 성공 에피소드 수를 구분한다.
- 보상·목표·허용오차·관절 범위를 학습 도중 자동 변경하지 않는다.
- NaN/물리 자산 오류/OOM/명시적 사용자 중단 때만 예외적으로 중단한다.
- 학습 완료 후 fresh reset 독립 평가 성공10회 이상을 별도로 확인한다.
- 전체 JM 월드 4대 동시 평가는 저장된 체크포인트로 별도 실시한다. 진행 중 학습의 보상·초기화·체크포인트를 변경하지 않는다.

## 랙 목표

`rack_goals.json`은 현재 JM 월드의 실제4개 랙 AABB를 읽어 저장한 매핑이다.
모두 같은 앞줄 랙으로 골라 접근 통로를 단순하게 구성한다.

| 슬롯 | RL용 로봇 | 기존 로봇 | 랙 | 도킹 월드 XY(m) |
|---|---|---|---|---|
| 1 | H1_1 | H1_1 | cont_008 | 36.175,18.255 |
| 2 | H1_3 | Atlas_1 | cont_009 | 38.425,18.255 |
| 3 | H1_2 | H1_2 | cont_000 | 48.575,18.255 |
| 4 | H1_4 | Atlas_2 | cont_015 | 28.225,18.255 |

방향은+Y(90도), 랙 앞면과 골반 기준점 거리0.60m다.
초기 위치는 목표1.2m 앞이다. 605개 활성 비로봇 collider에 대해 4개 직선 접근 통로의 AABB 사전 검사에서 지면 외 겹침은 0개였고, 4대 모두 F2 slab 위에 있다. **이 검사는 동적 충돌 안전이나 도달 성공을 증명하지 않는다.**
접근 정책은 랙 기준 상대좌표로 학습하고, 배치 좌표는 평가 때 변환한다.

## 파일과 실행

```text
jm_coop4_rl/
├─ h1_rack_env.py        독립 RL 환경/보상/종료/동결 보행 연결
├─ train.py              PPO 새 학습·체크포인트·상태 로그
├─ run_train.ps1         로컬 실행 (기존 출력 덮어쓰기 방지)
├─ extract_rack_goals.py 원본 월드 읽기 전용 목표 추출
├─ build_h1_fleet.py     원본 보존, H1 4대 추가 합성 및 무결성 검사
├─ eval_fleet.py         공장 월드 4대 실제 관절 구동·720p 별도 평가
├─ assets/              H1 4대 월드 overlay와 구성 검사 manifest
├─ rack_goals.json       4대/랙 매핑과 미검증 상태
└─ runs/<실험>/          manifest/status/history/checkpoint
```

```powershell
# 준비 검사
.\jm_coop4_rl\run_train.ps1 -RunName smoke_001 -NumEnvs 32 -Iterations 2 -Smoke
# 본학습, 새 actor 초기화
.\jm_coop4_rl\run_train.ps1 -RunName h1_nav_001 -NumEnvs 512 -Iterations 1000
```

최종 실행 상태는 `runs/<실험>/status.json`의 실제 값으로 판단한다.
코드 준비만으로 “학습 중”, “학습 완료”, “4대 랙 도착 성공”이라 표시하지 않는다.
