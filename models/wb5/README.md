# WB5 H1 보행 실행용 모델

`policy_lower_corrected.pt`는 현재 JM 실험에서 사용하는 고정 보행 actor입니다.
188,522 bytes이므로 일반 Git 바이너리로 포함합니다. Git LFS나 별도 다운로드가 필요하지 않습니다.

## 무엇을 포함하나

- 관측 69개 → 몸통/팔을 포함한 19관절 action을 출력하는 TorchScript 모델.
- 128 → 128 → 128 은닉층, ELU 활성화.
- 파일 SHA-256과 관측/관절 순서/기본각 명세: `manifest.json`.
- 해시 검사와 선택적 CPU 모델 로딩 검사: `verify.py`.

학습 재개용 **`model_1497.pt` 원본은 포함하지 않습니다.** 로컬에는 actor만 있고, 원본 서버 경로는 과거 기록만 확인됐습니다. critic/optimizer가 없는 이 파일을 전체 PPO 체크포인트처럼 `runner.load`에 넣으면 안 됩니다.
원본 없이 actor를 가져와 critic을 새로 학습하는 방식은 별도 warm-start 실험이지 기존 학습의 완전 재개가 아닙니다.

## 내려받기와 검사

```powershell
git pull --ff-only
python models/wb5/verify.py
# PyTorch 설치 환경에서 추가 확인:
python models/wb5/verify.py --load
```

검증 도구는 시뮬레이터를 실행하거나 로봇/모델을 수정하지 않습니다.
해시·출력 차원 검사 통과는 파일 배포 검증이며, 보행/회전 성능 합격이 아닙니다.

## 실행 코드와 연결할 때

이 배포의 모델 위치는 저장소 기준 `models/wb5/policy_lower_corrected.pt`입니다.
기존 로컬 실험 코드는 `artifacts/server_training_review_20260722/wb5/policy_lower_corrected.pt`를 참조합니다. 사용하는 실행기의 경로 설정을 새 배포 위치로 연결해야 합니다. 이번 배포에서 기존 실험 폴더나 현재 실행 경로는 변경하지 않았습니다.

월드만 열거나 actor만 로드해도 자동 보행하지 않습니다. `manifest.json`의 순서로 관측을 구성하고 관절을 이름으로 매핑해야 합니다. 이전 action은 초기화 시 0으로 시작합니다. 출력은 기본 관절각 + 0.5 × action으로 해석하며, 현재 배포 실행 주기는 물리 200Hz / 정책 50Hz입니다.
이 수치는 현재 실행 인터페이스를 설명할 뿐, 바닥 접촉·관성·초기화 등 학습/배포 물리 조건이 완전히 같다는 인증이 아닙니다.

## 확인된 상태와 한계

- 기존 WB5 모델 해시와 동일하며 가중치를 재학습/수정하지 않았습니다.
- 2026-09-30 JM 재현에서 141개 시점의 위치/yaw는 이전 실행과 일치하고 PD/effort/clock 검사도 통과했습니다.
- 그러나 -0.3rad/s 회전 진단에서 약 -21.25° 이후 정체해 회전 성능 기준은 실패했습니다.
- 물체 파지, 하중을 든 보행, 언로드 성공을 보장하지 않습니다.
- `model_999.pt` 등 상위 랙 내비게이션 모델(18입력/3출력)과 다른 모델입니다.

원본 학습 기록은 WB4 `model_1298`에서 자세 보상 변경 후 4096환경으로 200 iteration 추가 학습해 WB5 `model_1497`을 만들었다고 명시합니다. 이 계보는 문서 기록이며, 이번 업로드에서 원본 `model_1497` 파일을 직접 대조한 것은 아닙니다.
