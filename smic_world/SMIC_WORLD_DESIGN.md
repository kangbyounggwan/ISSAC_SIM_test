# SMIC World — 설계서 (KETI 컨셉(안) → Isaac Sim 실측 월드)

작성 2026-08-02 · 대상 `smic_world/` · 방법론은 JM 시화 월드와 동일(레이어드 USD)

---

## 1. 출처와 이 문서의 역할

입력은 **KETI 컨셉(안) 화면 캡처 1장**뿐이다. 실측 도면·치수표는 없다.
그래서 이 월드는 "그림을 따라 그린 것"이 아니라, 아래 두 축을 교차시켜
**치수를 역산한 결과**다.

1. **개념도의 상대 비율** — 휴머노이드 신장 1.75 m 를 스케일 바로 삼아 픽셀비 → 미터
2. **설비 클래스의 표준 실물 치수** — 3015급 평판 레이저, 갭프레임 프레스,
   KLT 600×400 물류 컨테이너, 작업대 높이 780 mm, 안전펜스 2000 mm 등

모든 숫자는 **가정값**이며 근거와 신뢰도를 §5 표에 항목별로 적었다.
실측이 들어오면 **`smic_layout.py` 의 숫자만** 고치면 월드 전체가 따라간다
(모델/빌드 스크립트에는 치수 상수를 두지 않았다).

> ⚠ 개념도의 말풍선 문구는 캡처 판독본이다. 일부 글자(특히 로봇 #1 역할의
> 첫 줄)는 해상도 한계로 확정이 어려워 최선 판독값을 넣었다. **원본 슬라이드로
> 검증 필요** — `smic_layout.CALLOUTS` 와 USD `customData.source` 에 명시해 두었다.

```
                                              │                         │
                                     빈 박스 랙 ◀┘               Press 완료 적재대
                                              │                         │
                                              └──▶ AMR Port ×3 ◀────────┘
```

## 3. 좌표계 규약

| 항목 | 값 |
|---|---|
| 축 / 단위 | **Z-up, meters** (루트 레이어에 각인) |
| 바닥 슬래브 top | `z = 0.0` — 모든 설비·로봇 발바닥 기준면 |
| +X | 개념도 왼쪽→오른쪽 (레이저 → 슬라이드 → 프레스 → AMR) |
| +Y | 개념도 앞쪽(관찰자)→뒤쪽(창문 벽) |
| 원점 | 베이 좌측-전면 안쪽 코너 |
| 스테이션 로컬 | +X=폭, +Y=깊이, z=0=바닥, **정면 = 로컬 −Y** |
| yaw | 월드 Z축 회전(도). 개념도 설비는 전부 정면이 −Y 라 yaw=0 |

건물 전면(−Y)은 개념도처럼 **컷어웨이** — 벽을 세우지 않아 카메라가 셀 안을 본다.
지붕은 존재하되 `MakeInvisible` (JM 관례).

## 5a. 겐트리 로더 — 왜 이 좌표밖에 안 되는가

레이저 베드와 슬라이드 고측을 잇는 반송 수단. **문형(portal) 오버헤드 겐트리**로
정한 이유와 각 수치의 제약은 다음과 같다.

**다리 위치 (x = 0.40 / 9.90) — 자유도 거의 없음**
레이저 풋프린트가 `x 0.80–6.00`, 슬라이드가 `x 7.83–9.38` 을 차지하고, 그 오른쪽은
펜스 `x=10.50`, 빈 박스 랙 `x≥10.95` 다. **바닥이 비어 있는 X 구간은 왼쪽 0–0.8 과
가운데 6.0–7.8, 오른쪽 9.4–10.5 뿐**이고, 이 중 스팬을 최대로 잡을 수 있는 조합이
0.40 / 9.90 이다. 중간 지주는 레이저 위에 떨어지므로 **불가** → 무지주 9.5 m 스팬
(판재 반송 겐트리로는 일반적인 범위).

**Y = 10.40 — 유일한 라인**
겐트리가 덮어야 하는 두 점은 ① 레이저 베드(`y 7.16–10.84`)의 후방 언로딩 존과
② 슬라이드 고측이다. 슬라이드 데크는 y 가 커질수록 높아지므로 적재 지점은 후방이어야
하고, `y = 10.40` 에서 데크 top = **2.02 m** 다. 두 조건을 동시에 만족하는 Y 대는
10.2~10.8 뿐이며 그 중앙값을 잡았다.

**브리지 하단 z = 3.90**
아래를 지나는 설비 실측 최고점은 슬라이드 후단 프레임 **2.80 m** (레이저는 1.63 m).
여유 **1.10 m** 확보. 검증기가 매번 `station_bbox` 로 straddle 대상을 찾아
합성 bbox 최고점과 비교한다(하드코딩 아님).

**침범 검사 처리**
겐트리는 다른 설비를 **타넘는** 유일한 구조물이라 전체 bbox 로 겹침을 보면 레이저·
슬라이드와 항상 충돌로 잡힌다. 그래서 스테이션 스펙에 `ground_boxes`(바닥에 실제로
닿는 부분의 로컬 풋프린트)를 도입하고, 침범·클리어런스 검사는 전부 이걸 쓴다.
겐트리는 다리 2개(0.70 × 0.90)만 접지한다. 펜스 라인과의 간섭도 별도 검사에 추가했다
(오른쪽 다리 ↔ 펜스 `x=10.50` 여유 0.22 m).

**구성**: 베이스플레이트 + 박스컬럼(옐로 안전밴드) + 헌치 + 박스거더 브리지 +
캐리지 주행레일 + 케이블 드래그체인 + 점검 핸드레일 + X 주행 캐리지 +
2단 텔레스코픽 Z 마스트 + 진공 리프터 헤드(석션컵 3×2) + 신호등.
현재 포즈는 캐리지가 **레이저와 슬라이드 사이(월드 x = 7.20)**, 헤드 z = 2.70,
판재 1장을 물고 있는 상태(정적 콜라이더 — 낙하 금지). `carriage_x` / `head_z` 로 조정.

## 6. 로봇 배치와 리치 검증 — **이 월드의 핵심 제약**

JM 실측: H1 은 토르소 피치가 없어 **베이스(골반) 기준 정면 파지 상한 0.88 m**.
개념도는 로봇 한 명이 팔을 벌려 좌·우 박스를 동시에 다루는 그림이지만,
그 배치를 그대로 쓰면 분류 테이블 양끝 박스가 1.13 m, 프레스 다이가 1.65 m 로
**전부 상한 밖**이다.

그래서 "한 자리에서 다 닿는" 배치를 포기하고, **타깃마다 정면 0.75 m 오프셋의
작업 스팟**을 따로 두는 구조로 설계했다(사람이 옆으로 스텝하며 작업하는 방식).
스팟은 `_stand()` 가 타깃에서 자동 산출하므로 손으로 고치면 검증이 깨진다.

| 스팟 | 타깃 | reach (m) | 설비 클리어런스 (m) |
|---|---|---|---|
| R1_SLIDE_L / R | 슬라이드 좌/우 레인 랜딩 | 0.750 | 0.27 |
| R1_SORT_0 / 1 / 2 | 제품#1 / 제품#2 / 프레스대기 박스 | 0.750 | 0.35 |
| R1_RACK | 빈 박스 랙 | 0.750 | 0.30 |
| R2_PRESS | 프레스 다이 (z 1.05) | 0.750 | 0.25 |
| R2_OUT_0 / 1 | Press 완료 적재대 | 0.750 | 0.35 |
| R2_AMR_P1 / P2 / PR | AMR Port 박스 | 0.750 | 0.28 |

**12/12 PASS** (`verify_smic_world.py`).

설계상 결정 두 가지:

- **프레스 다이를 베드 전면으로 −0.70 m 당겼다.** 안 그러면 다이가 베드
  1.1 m 안쪽이라 어떤 자세로도 못 닿는다. 실제 갭프레스도 투입을 위해
  다이를 전면에 둔다. 대신 로봇이 베드 앞면에서 0.25 m 까지 붙는다(정강이 여유).
- **AMR Port 는 후면(+Y, 작업통로)에서 접근한다.** 전면(−Y)은 AMR 주행·도킹
  공간이라 로봇이 설 수 없다. 개념도의 AMR 위치(포트 앞)와 모순 없이 성립한다.

기본 포즈: 로봇#1 은 개념도처럼 **분류 테이블(관찰자 쪽)을 보고 서고 슬라이드가 등 뒤**
(8.60, 6.70, yaw −90). 로봇#2 는 프레스 정면 (15.60, 7.75, yaw 90).

| 지지면 콜라이더 | 테이블 상판·선반·데크·베드·다이·랜딩·가이드에 명시 부여 | JM 교훈 — 빼먹으면 물건이 설비를 **관통해 떨어진다** |

소유 프림 기준 콜라이더 254, 동적 강체 26.

> **알려진 제약**: 참조하는 `h1_gripper.usda` 의 각 링크 `*/collisions` 가 **비어 있다**
> (링크 40 / 콜라이더 0). 렌더·배치·리치 검증에는 문제 없지만 **물리 파지·보행 전에는
> 로봇 에셋 쪽 콜라이더 보강이 필요**하다. 월드 문제가 아니라 공용 로봇 에셋 문제이고,
> `verify_smic_world.py` 가 매번 경고로 띄운다.

## 8a. 외부 DCC(블렌더) 왕복

`export_smic_obj.py` / `import_obj_asset.py` 로 왕복한다. 상세 사용법은 README 참조.
설계상 중요한 결정만 여기 남긴다.

**형상과 물리를 분리한다.** 블렌더에서 다듬은 메시는 *보기용*, 원래의 절차적 박스는
*충돌용*으로 계속 쓴다. `--replace` 는 원본 스테이션을 **숨김 처리만** 하는데
USD 에서 visibility 는 물리에 영향을 주지 않으므로 콜라이더가 그대로 살아 있기 때문이다.
고해상도 메시를 그대로 콜라이더로 쓰면 PhysX 비용이 폭증하고 파지가 불안정해진다.
꼭 필요하면 `--collision convexHull` 로 볼록 근사만 건다.

**단일 진실원이 깨지는 지점.** 어떤 설비를 외부 메시로 교체하면 그 설비에 한해
`smic_layout.py` 의 치수가 더 이상 형상을 지배하지 않는다. 교체 사실은
① USD `customData.replaced_by` / `customData.replaces` ② `smic_custom_assets.json`
양쪽에 남긴다. **리치·클리어런스 검증은 여전히 layout 의 숫자로 돈다** —
외부 메시의 실제 외형이 layout 치수와 어긋나면 검증이 거짓 PASS 를 낼 수 있으므로,
교체 시 layout 의 해당 `size` 도 실제 메시에 맞춰 갱신할 것.

**제네시스와의 관계.** `SMIC_FORCE=1` 재빌드는 서브레이어를 비우므로 편입이 지워진다.
그래서 편입은 원장에 기록해 두고 `--replay` 로 재적용하는 **후처리 단계**로 설계했다
(제네시스를 외부 에셋에 의존하게 만들지 않기 위한 의도적 분리).

**축.** OBJ 는 Y-up, USD 월드는 Z-up. 내보내기 `(x,y,z)→(x,z,−y)`,
되가져오기 `(x,y,z)→(x,−z,y)`. 라운드트립 bbox 일치로 검증했다.

**블렌더 4.5.1 실측 함정 3종** — `blender_setup_smic.py` 가 자동 보정한다.
1. USD 의 `displayColor` 는 머티리얼이 아니라 **컬러 어트리뷰트**로 들어온다
   (메시 556 중 529 가 머티리얼 없음). Attribute 노드로 Base Color 에 물려야 한다.
2. 조명이 **Isaac RTX 강도 그대로** 들어와 렌더가 순백이 된다(Sun 1600 / Rect 2600).
3. 카메라 focalLength/aperture 가 **100배**로 들어온다(16 mm → 1600 mm).
   FOV 비율은 보존되지만 1600 mm 렌즈의 피사계심도가 0 이라 화면이 뭉갠 회색이 된다.
   위치·방향은 정확하므로 lens/sensor 만 되돌리고 DOF 를 끄면 된다.
   → 셋업 스크립트 적용 후 Cycles 로 ConceptCam 렌더가 Isaac 렌더와 동일 화각으로 나오는 것까지 확인.

## 9. 실측이 들어오면 고칠 곳

전부 `smic_layout.py` 안이고, 고친 뒤 `SMIC_FORCE=1` 재빌드 + `verify` 만 돌리면 된다.

1. `BAY` — 베이 실치수
2. `STATIONS[*]["center"]`, `["size"]` — 설비 좌표/치수
3. `BOX`, `PLATE` — 실제 컨테이너 규격, 판재 재질/두께/질량
4. `FENCE_SEGMENTS`, `LANE_SEGMENTS` — 안전펜스 실제 경로, 도장 라인
5. `REACH_MAX`, `STANDOFF` — 실기 로봇이 H1 이 아니면 여기부터
