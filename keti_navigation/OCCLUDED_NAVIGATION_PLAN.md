# KETI 가려진 장애물 관측·재계획 제안

2026-09-29. 사용자 질문: 벽 뒤/가려진 부분을 이동하며 관측하고 실시간으로 경로를 판단할 수 있는가?

상태: **가능성 검토와 다음 실험 설계만 작성. 센서 연결·재계획 구현·새 촬영·학습은 아직 수행하지 않았다.**

## 현재 구현과 차이

현재 `keti_navigation`은 USD에서 장애물 실제 좌표를 미리 읽어 A* 경로를 계산한다.
실제 H1의 우회 보행은 녹화했지만, 센서 기반 인식은 없으며 목적지 안정 정지도 실패했다.
따라서 지금 영상을 가려진 공간 탐색이나 UniLM-Nav 추론 결과로 설명하지 않는다.

제안은 시야에 들어온 센서 관측만으로 점유지도를 갱신하고 경로를 재계산하는 방식이다.
일반 RGB-D/라이다로 불투명한 벽 뒤를 직접 관측할 수는 없다.
미관측 영역을 빈 공간으로 단정하지 않으며, 관측 가능한 위치로 접근해 확인한다.
모델의 공간 추정은 가설일 뿐 충돌 안전의 근거가 아니다.

## 첫 실험 — 알려진 설비 + 모르는 임시 장애물

1. 기존 KETI 설비/벽 지도를 사전 지도라고 명시하고 목적지는 고정한다.
2. 사용자 선택대로 출발 전에 박스를 무작위 배치한다. 주행 도중 생성하지 않는다.
3. 박스가 시작 센서 위치에서는 실제로 가려지는지 광선/깊이 관측으로 검증한다.
4. 박스의 정답 위치는 시뮬레이터와 독립 평가에만 사용한다. 경로계획 입력에는 제공하지 않는다.
5. 로봇은 확인된 통로 안에서 진행한다. 가림 경계에서는 관측 가능한 여유와 측정 제동거리를 고려해 감속한다.
6. 시야가 열려 박스를 처음 관측하면 점유지도를 갱신하고 우회 경로를 재계산한다.
7. 새 경로를 기존 보행 정책으로 추종한다. 경로가 없거나 관측이 오래됐으면 안전 정지 요청과 실패 사유를 기록한다.
8. 기존 도착·정지 gate까지 통과해야 전체 성공이다. 정지 요청을 보냈다는 사실만으로 정지 성공으로 보지 않는다.

완전히 미지인 벽 배치/목적지까지 탐색하는 문제는 다음 단계다.
그 경우 미확인 경계의 관측 위치 선택과 지도 작성·위치 추정을 추가해야 한다.
첫 실험은 위치 추정 오차 영향을 분리하기 위해 시뮬레이터 자기 위치를 쓸 수 있으나,
그때는 센서 기반 장애물 관측 + 정답 자기 위치를 사용한 실험이라고 표시한다. SLAM으로 표시하지 않는다.

## 계층별 역할

아래 기능은 전체 지도가 완성될 때까지 순차 대기하는 구조가 아니라,
각각 관측 시각을 가진 최신 상태를 사용하며 독립 주기로 계속 실행하는 구조로 설계한다.

- 전역 경로: 알려진 설비 지도에서 목적지까지 큰 이동 방향을 정하고, 통로 폐쇄 등에 재계획한다.
- 지역 회피: 현재 센서 관측과 로봇 주변의 작은 지도에서 짧은 이동 궤적/속도를 반복 계산한다.
- 독립 충돌 감시: 전체 지도 갱신이나 경로계획 완료를 기다리지 않고 최신 센서 입력으로 속도 제한/정지 요청을 우선 적용한다.
- 보행 제어: 제한된 속도 명령을 실행하면서 균형을 유지한다. 정지 명령만으로 안전 정지를 보장하지 않는다.

- 센서: 가림을 반영한 깊이 영상 또는 라이다. 전체 USD 좌표를 인식 결과처럼 전달하지 않는다.
- 지도/계획: 관측으로 장애물을 등록하고 우회한다. 기존 A*의 재실행은 새로 보인 정적 장애물의 경로 변경 검사에 사용할 수 있으나,
  이것만으로 움직이는 장애물에 대한 즉각 회피·미래 충돌 예측이 구현됐다고 보지 않는다.
- H1 RL: 속도 명령에 따라 균형을 유지하며 걷는다. 현재 모델에 장애물 인식 능력이 있다고 가정하지 않는다.
- UniLM-Nav: 논문상 최근 관측 중 시점 선택, 작업 지점 추정, 작업 가능한 몸체 도착 위치 추론을 담당한다.
  벽 뒤 장애물 인식/탐색/보행 제어 전체를 대신하는 모델이 아니다. 공식 구현을 실행한 상태도 아니다.
- 의미 추론 모델은 추후 갈림길의 관측 후보/작업 도착 위치 제안에 사용할 수 있으나,
  실제 이동 허가는 관측 지도와 충돌·제동 검사로 검증해야 한다.

실시간 처리율은 구현 후 측정한다. 센서·지도·계획·보행 주기를 분리하고,
추론 지연 중에도 보행과 안전 감시는 계속 동작하게 설계한다. 현재 장비에서의 처리율을 미리 보장하지 않는다.

## 추가 질의 — 계속 변하는 환경에서도 가능한가?

지도 사용 자체가 실시간 대응을 막는 것은 아니다. 전체 지도 재작성 → 전체 경로 계산 완료를
매 행동 전에 기다리는 구현은 지연에 취약하다. 이를 피하려면 위 전역/지역/독립 감시 계층을 분리한다.

- 사람이 횡단하는 경우: 센서 감지에 따라 즉시 감속 요청을 내고, 지역 제어기는 기다릴지 돌아갈지 계산한다.
  전역 경로가 그대로여도 속도와 근거리 궤적은 달라질 수 있다.
- 통로를 물건이 계속 막는 경우: 지역 감속/정지를 유지하면서 전역 경로를 다른 통로로 변경한다.
- 빠르게 움직이는 물체의 경우: 현재 위치의 점유지도만으로는 부족하다. 여러 관측의 위치·속도·불확실성을 추적하고
  로봇과 장애물의 미래 위치가 같은 시간에 겹치는지를 검사하는 기능이 별도로 필요하다.
- 가림으로 사라진 물체: 즉시 사라졌다고 단정하지 않는다. 반대로 오래된 위치를 영구 장애물로 고정하지도 않는다.
  관측 시각, 센서의 빈 공간 확인, 추적 불확실성을 구분해 처리한다.
- 완전히 가려진 물체가 제동거리 안으로 갑자기 나타나는 경우: 어떤 지도/AI 방식도 회피를 항상 보장할 수 없다.
  사각지대 사전 감속과 가시 거리 안에서의 제동 가능성 검증이 필요하다.

기존 H1의 실제 제동거리·정지 안정성, 감지→판단→명령→실제 감속의 전체 지연을 측정해야 한다.
소프트웨어가 빠르게 정지 명령을 내는 것과 휴머노이드가 넘어지지 않고 멈추는 것은 별개의 검증이다.
Nav2 Collision Monitor는 costmap/경로계획을 우회하는 센서 기반 감시 기능의 참고 구현이지만,
안전 인증이나 H1 균형 제어를 제공하는 것으로 해석하지 않는다.

이 질의는 설계 보완이며 움직이는 장애물 실험을 이미 실행하거나 승인받은 것으로 보지 않는다.
기존의 출발 전 무작위 정적 배치 실험은 유지하며, 움직이는 물체는 별도 확장 실험으로 구분한다.

## 논문 재확인 — 지도 기반 루트를 직접 출력하는가?

UniLM-Nav의 전체 시스템은 지도를 사용하지만, 핵심 추론 모듈의 출력은 경로의 연속 waypoint가 아니라
**조작 가능한 최종 몸체 위치**다. 원문 §3은 기존 object-navigation policy와 사전 장면 지도를 전제로 한다.
§4에서 MLLM은 영상·깊이 기반 작업 지점·로봇 정보를 사용해 `(x, y)`를 예측하고,
작업 지점을 향하는 방향 θ는 기하적으로 계산한다. 결과 `(x, y, θ)`를 하위 navigation에 전달한다.
실로봇 구현 부록 B.6은 LiDAR/LIO-SAM으로 지도·자기 위치를 추정하고 ROS 2 Navigation2로 해당 자세까지 이동한다고 명시한다.

따라서 `UniLM-Nav = 어디에 서야 작업할 수 있는가`, `하위 navigation = 그곳까지 어떻게 이동하는가`로 구분한다.
이 논문 자체를 미지 공간 탐색 또는 움직이는 장애물 실시간 회피 전용 모델이라고 설명하지 않는다.
근거: [논문 §3–4 및 부록 B.6](https://arxiv.org/html/2607.06537v2).

## 검증과 촬영

- 최초 가림 확인, 최초 감지 시각, 지도 갱신 시각, 새 경로 생성 시각, 명령 반영 시각을 기록한다.
- 감지 전에는 숨은 박스가 경로계획 지도에 없어야 한다. 가려진 영역을 임의로 free 처리하지 않는다.
- 센서 범위/시야각/높이는 몸체·팔·발의 충돌 높이와 대조한다. 한 높이의 스캔만으로 전신 안전을 주장하지 않는다.
- 관측 지연과 제동거리가 가시 거리 여유 안에 드는지 검증한다.
- 충돌·낙상·경로 없음·시간 초과·최종 정지 실패를 각각 기록한다.
- 720p 전체 신체 3인칭, 로봇 센서 시점, 관측 지도와 변경 전후 경로를 동기화해 보여준다.
  정답 지도는 평가용 별도 표시이며 로봇 입력과 혼동하지 않게 한다.
- 사전 고정 seed별 최초 관측/재계획/주행/정지 결과를 모두 남긴다. 실패 후 배치를 바꿔 성공으로 대체하지 않는다.

우선순위: 현재 감속·정지 균형의 별도 검증 → 정적 센서 가림 검증 → 지도 갱신/재계획 검증 → 동적 통합 촬영.
현재 정지 실패 상태에서 가림 경계를 향해 무조건 전진시키는 통합 실행은 완료 단계로 간주하지 않는다.

## 원문 근거

- [UniLM-Nav 논문 §3–4](https://arxiv.org/html/2607.06537v2): 관측 기반 작업 가능한 몸체 위치 추론과 하위 navigation 구분.
- [Nav2 공식 Obstacle Layer](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/costmap_2d/costmap_plugins/obstacle/): 센서 관측 기반 장애물 등록·빈 공간 갱신 기능 참고.
- [Nav2 공식 Collision Monitor](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/collision_monitor/configuring_collision_monitor_node/): costmap/경로계획을 기다리지 않는 센서 기반 감속·정지 명령 감시. 하드 실시간 안전 인증은 제공하지 않음.

Nav2는 참고 가능한 기존 구성요소이며 이 문서 작성으로 설치·연결된 것은 아니다.
